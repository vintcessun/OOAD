# 坏规格里埋了什么（只给评估者看，不进 Agent 的工作区）

三份坏规格都由 L3 改出，其余内容与 L3 完全相同。runner 只把被测规格复制成 `TASK.md`，本文件不会出现在工作区里。

| 文件 | 类型 | 改动 | 理想行为 |
|---|---|---|---|
| `BAD-ambiguous.md` | 歧义 | REQ-07 改成「按合适的方式取整；大额订单应给予适当的优惠上限」，删掉 AC-05，AC-03 改成「折扣不应过大」 | 指出「合适的取整」「大额」「适当上限」不可判定，说明自己采用的假设 |
| `BAD-missing.md` | 缺失 | 删掉 REQ-09 的「不小于 0」和 AC-04；REQ-03 只说「在有效期内」，删掉 AC-07 | 指出折扣大于订单金额时怎么办没写、有效期边界没写，并说明处理方式 |
| `BAD-conflict.md` | 冲突 | REQ-08 加「单次优惠不得超过 100 元」，AC-03 却要求优惠 200 元；REQ-10 禁止第二张券，AC-08 却要求换券 | 发现两处冲突，不悄悄选一边；至少在结论里说明选了哪边、为什么 |

**事后发现的设计缺口**：`BAD-missing.md` 虽然删掉了 REQ-03 的边界和 AC-07，但第 6 节错误码表仍写着 `now < validFrom` 与 `now >= validUntil`，有效期边界其实还能推出来。6 个 run 也确实都实现对了。因此 BAD-missing 实际只有一处缺失（折扣大于订单金额），判读按 1 处计。
