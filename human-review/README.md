# 六人源码人工审查分工与执行方案

六人按业务链分工，每人约两天。主审人从页面或API入口追到业务规则、查询、事务及返回；共享边界由第二人挑战并复核。审查重点是独立业务预期、组合操作、跨层身份与范围、失败后的最终状态。

## 范围与当前基线

审查权限中心后端、管理控制台、接口契约、数据库迁移、测试、设计模型及相关构建运行配置。不审查rbac-mock-biz，不要求模拟外部业务系统运行。独立导论实验、归档设计、构建产物和本地密钥不属于本轮源码范围。

基线提交：a42b8018d6a9c9051fd527dcae05a8da04746082；准备日期：2026-10-15。文件实际内容以[inventory.json](inventory.json)中的指纹为准，文本忽略CRLF/LF差异。共享工程文件只读权限中心及控制台相关段。当前范围内169个文件有主审归属，45个API有链路卡，68个后端测试方法有断言审查责任人。

项目为RBAC0与部门子树作用域。后端采用Controller → Service → Mapper，Entity/DTO/Config为辅助结构；Mapper使用JPA、JPQL及部分原生SQL。部门树不是角色继承。接口声明与目标范围检查处于不同位置，不能只读其中一层。

## 高效阅读方法

1. 先共同定义调用者、目标用户、用户所属公司/部门、角色所属公司、指派适用部门、账号/角色状态、selfOnly、SA旁路与指派回收。
2. 每个功能先写业务预期及依据，再读实现条件。规则冲突记为待确认，不能把代码现状当作业务规则。
3. 沿页面 → API封装 → 契约权限 → Controller → Service/helper → Mapper/SQL → 提交/回滚 → 返回与刷新完整追踪。读接口也核对总数、分页、范围外信息泄露。
4. 优先推演本人/同级/上级/SA、兄弟部门/其他公司、停用/删除/过期、调岗、先缓存后撤权、重复提交、中途失败与请求乱序。
5. 并发填写T1/T2执行顺序；事务填写最终表、版本、缓存和审计状态。不以注解存在或使用并发容器作为正确性结论。
6. 测试核对请求确实到达目标分支。403要看拒绝位置与原因；SA执行的测试不能证明普通管理员范围检查正确。失败要断言无残留写入及范围外数据不变。

## 完成标准

- 45个API各有主审、独立预期、完整间接调用、最终查询、事务、副作用和前端反馈记录。
- 范围内文件有实际阅读状态，高风险结论有第二人复核，规则疑点有团队决策。
- 所有授权写入核对上界、版本更新、事务与审计；批量核对范围、重复、分块和原子性。
- 测试证据注明提交、环境、时间、命令、断言及覆盖率排除项；测试方法存在不等于运行通过。
- 每人交付阅读清单、API链路卡、问题记录、复核记录。不以问题数量或覆盖率高低替代业务正确性。

本包建立审查任务与可填写底稿，人工阅读、复现、规则决策和签字待完成；不修改业务API、数据库或实现。必要复现仅在隔离测试环境进行，测试基类会清库和清Redis。
