安全依赖修复后最终本地标签 `local-final-20261115-035858`：分别选择structured、DDD执行两轮七服务验收，每轮7/7服务、11/11探针通过，最终保留DDD。
两轮复用相同中心/课程前端镜像；MySQL/Redis容器与数据卷未变。TLS1.3、私有路径403、未认证课程401、内部健康、MySQL healthy、Redis PONG和实际镜像SHA256匹配均有记录。
完整不可变镜像/容器ID、两轮探针及停写切换证据见link:../deploy/deployment-evidence.json[真实运行证据]。
这两轮的拓扑见 link:design/swarm-deployment.svg[七服务验收图]。

这是本机Docker Desktop单manager的授权隔离Swarm，不是外部生产或三服务器高可用验收。TLS证书本地自签，不冒称公共可信CA；未提供的远端条件、容量与整机恢复未验证。

== 当前六服务拓扑与运行环境

image::design/swarm-deployment-current.svg[当前 Compose 的六服务拓扑]

link:design/swarm-deployment-current.png[PNG] · link:design/swarm-deployment-current.puml[PlantUML 图源]

* Java21、中心Spring Boot3.3.5、Maven3.9.9、MySQL8、Redis7、Node22/Vue3。
* 稳定服务名rbac-backend通过MODULE选择rbac-structured或rbac-ddd，仅一个活动中心；两套业务实现不共用服务代码。
* 当前 Compose 使用 `rbac-web`、`rbac-backend`、`course-web`、`course-backend`、`mysql` 和 `redis` 六项服务。
* 默认只公开两个前端的 TLS 入口，中心使用 `https://localhost:8443`，课程使用 `https://localhost:9443/course/`。
* 中心前端将 `/api`、`/auth`、`/.well-known` 转发给权限后端。课程前端将 `/login` 和 `/api/login` 交给课程后端，将 `/auth`、`/.well-known` 和受保护的 `/api/` 请求交给权限后端。内嵌的 `CourseProxyFilter` 完成鉴权后，经 `COURSE_UPSTREAM` 转发课程业务请求。
* 两边缘拒绝/integration和/identity；可信服务key不进入浏览器、镜像环境明文或日志。
* 生产RSA通过共享文件和Swarm secrets，不使用临时key；configtree提供数据库口令、bootstrap和服务key。角色/权限不放JWT，注销事实存MySQL。

== 安全边界

RBAC1 V1/V2 用于初始化新库。Flyway 随发布应用未运行的 V3–V5，分别更新角色启停权限、课程身份目录和登录登记，以及部门启停与删除权限。保留 Flyway 历史及校验和，旧 RBAC0 库须另行迁移。
构建/测试实例仅loopback13306/16379，课程测试13316，与部署私有数据卷隔离；禁止把运行中的部署数据库当测试库。
任何脚本不得prune、删除旧服务/卷、误杀共享JVM或操作其它stack；旧服务名冲突应拒绝并请求维护窗口，不自动迁移。

运行秘密默认保存在被忽略的 `.runtime/full/`，Unix owner-only、Windows显式当前用户ACL；只生成缺失文件，不覆盖已有RSA/证书/口令。
root在DDL中只有UNINITIALIZED占位，首次启动从bootstrap-password初始化，没有固定公开root口令。首次使用应改密；bootstrap只作用于未初始化账号，不是改密后的密码恢复入口。

== 构建与质量门槛

先按link:test-plan.adoc[测试计划]正常执行JUnit和真实HTTP，再执行原覆盖门槛。原70%行/60%分支、service85%均保留，DDD application也执行同85%。
不能用skipTests打包冒称测试通过；最终verify的skipTests仅避免重复前序已真实运行的JUnit，仍合并HTTP exec、report及check。

[source,shell]
----
# 显式JAVA_HOME21；专用测试服务及实际测试凭据已就绪。
bash tools/install-clonefactory.sh
bash tools/prepare-course.sh --build
./mvnw clean package
source deploy/full-jacoco-agent.sh
export ACCEPTANCE_DB_PASSWORD='<专用测试实例凭据>'
(cd tools/acceptance && npm ci && npm test && npm run acceptance)
./mvnw verify -DskipTests
----

前端须运行 typecheck、Vitest 覆盖率、构建和两实现桌面 Chromium E2E。教师原440测试和真实双中心六类12联调分别记录。参见 link:acceptance/frontend-redesign.adoc[桌面前端验收]。
当前精确canonical jar为各模块 `target/<module>.jar`，Dockerfile不再用通配符误装候选/旧包；课程使用固定上游的单一精确jar。

== 可复现本地Swarm验收

参数模板为 `deploy/full-env.example`，显式环境优先于.env；非法MODULE在副作用前拒绝。秘密值只在本机受控设施设置，不粘贴进仓库或共享终端。

[source,shell]
----
bash deploy/full-secrets.sh
# 仅在本机尚未初始化Swarm、且操作者确认该独立Docker环境可用时初始化；不操作已有远端集群。
# docker swarm init
SHARED_REPORT='<最新全绿shared report.json绝对路径>' \
REACTOR_LOG='<全模块门槛成功日志绝对路径>' \
bash deploy/full-final.sh
----

final gate先校验真实Surefire最少2/49/112/25且无失败/错误/skip、两个25场景及T21成功、全模块verify成功、可执行jar及当前jar等于HTTP运行快照；任一未过都在镜像构建前拒绝。
脚本创建不可覆盖的 `local-final-*` 标签，构建两套中心镜像和共用应用镜像后再次检查 JAR，再执行 Structured 和 DDD 两轮受控切换与运行验证。
每次切换先停写，等待旧的两个前端和两个后端停稳，保留 MySQL、Redis 和数据卷，再发布新模块。

[source,shell]
----
# 只查看本任务新stack，不扩展到其它项目。
docker stack services rbac1-acceptance
MODULE=rbac-ddd TAG='<当前部署的不可变标签>' DEPLOYMENT_STAGE=local-final \
EVIDENCE_FILE=.runtime/full/manual-recheck.json bash deploy/full-verify.sh
----

最终证据使用自己的immutable tag；重新验证时需选择同一个真实TAG，不能用local默认tag冒充已部署版本。
回滚只在已验证的RBAC1镜像/配置间按同样停写屏障操作，不能把一期RBAC0旧镜像直接接到新基线。

== 初次业务使用

. 在本机安全取得 `.runtime/full/bootstrap-password`，中心以root登录并自行改密。
. 通过中心管理UI建立业务部门及course-project-management的准入角色，创建合成/授权账号，分别指派admin、teacher、student。不要删掉总部SUPER_ADMIN准入以免触发最后管理员保护。
. 课程管理员在真实课程系统维护Teacher/Student与中心稳定subject的绑定；不按名字猜身份，不伪造teacher/CC。
. 使用业务账号从课程前端登录。中心root不是隐式课程teacher；copyCourse仍需全局teacher及组长/真实CC对象规则。

自动化联调使用独占新库、真实中心API和合成数据，见link:../course-integration/REAL-CENTERS-VERIFICATION.md[12例证据]，不把测试fixture灌入部署数据卷。

== 仍未声称的事项

* 外部服务器、外网域名/公共证书、镜像远端发布与三节点HA不是本地证据覆盖的范围。
* 未对其它服务、旧库或现有生产卷做迁移、停机、删除、恢复演练。
* 中心与课程跨库同步HTTP不是分布式原子事务；业务提交而审计未确认的503窗口及同UUID有限重试必须如实保留。
* GitHub CI状态需在最终push后按实际run核对，不能把本地通过称为远端CI成功。
