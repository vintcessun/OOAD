== 适用范围与唯一来源

当前共享开发基线为MySQL 8、InnoDB、utf8mb4与UTC TIMESTAMP(3)，不是一期RBAC0结构。
link:schema-contract.adoc[冻结物理列合同]规定15张业务表的精确列、可空性和约束；两个后端实体/领域对象可独立设计，但不得更换物理字段。
结构化配置Hibernate ddl-auto=none，DDD配置ddl-auto=validate；建表均由Flyway，不以Hibernate自动更新替代迁移。

RBAC0 的旧 V1–V4 保留在 Git 历史。当前 RBAC1 的 V1/V2 初始化空库，Flyway 按库的现有版本应用 V3–V7。V5 使用已有的 `sys_department.status` 列，现有部门状态保持原值。
禁止将新基线连接生产或已有一期库、篡改其Flyway历史/checksum、clean生产、用baseline-on-migrate掩盖冲突。
已有旧库应继续使用匹配的一期镜像/schema；需要升级时另行制定备份、兼容迁移与恢复方案，本轮不操作旧库。
打包前clean构建，避免target/classes残留旧脚本进入jar。

== 15表及职责

[cols="1,3"]
|===
|表 |关系与关键约束
|sys_system |code唯一；status与version；系统码rbac-center、course-project-management。
|sys_department |parent_id自引用、code唯一、path；用户唯一所属部门；总部path=/1/。
|sys_user |subject和username各自唯一；password_hash、name、no、phone、department_id、status、token_version、must_change_password、failed_login_count、locked_until、version、created_at。用户名不可复用；无company或到期列。
|sys_role |system_id归属系统，UNIQUE(system_id,code)；description、status、builtin、version。
|sys_permission |UI/API分种类，UNIQUE(system_id,kind,code)；启停与version。
|sys_role_permission |角色直接权限，UNIQUE(role_id,permission_id)；继承权限不冗余写回。
|sys_user_role |直接指派，UNIQUE(user_id,role_id)；assigned_by可空且关联用户，assigned_at。无scope部门。
|sys_department_allowed_role |部门直接角色准入，UNIQUE(department_id,role_id)；准入不等于自动指派。
|sys_role_hierarchy |senior_role_id→junior_role_id，联合唯一，CHECK拒绝自环；允许多父，仍须事务验环。
|sys_ui_resource |同系统MENU/BUTTON树，parent_id自引用，permission_id关联UI权限；route/component可空；UNIQUE(system_id,code)。
|sys_api_operation |真实operation_id、method、path_template、permission_id、required_role、access_policy、enabled、version；系统内operationId与method/path分别唯一；PROTECTED至少有权限或角色条件。
|sys_ui_api_mapping |UI资源/API操作显式多对多；联合唯一。仅追踪，不隐式赋权。
|sys_token_revocation |jti主键、subject、expires_at、created_at；MySQL权威撤销事实，不依赖Redis存活。
|sys_grant_version |固定id=1、version；全局授权写互斥/缓存版本，不是JWT token_version或实体乐观锁。
|sys_audit_log |request_id全局唯一；source_system_code、origin、操作者快照、event_type、object_type/object_id、target、前后JSON、result/reason、trace_id、payload_hash、occurred_at；不建业务FK。
|===

完整类型及NOT NULL/NULL逐列以schema合同与V1为准。普通外键防孤儿；同系统、UI/API kind、树/DAG无环、最后超级管理员与授权上界由持锁写事务负责，不夸大为SQL CHECK已全部表达。
MySQL不允许CHECK引用自增id，部门/UI树自指和长环必须在服务/领域事务中校验。

== 授权写事务与缓存

授权事实变化先排他锁sys_grant_version(id=1)，再修改系统/角色/权限、继承/映射/指派/准入或用户状态/部门；最后version+1及SUCCESS审计与业务一起提交。
部门实际启停使用同一事务推进授权版本并写入 `DEPARTMENT_STATUS_CHANGED`。停用保留成员和关联记录，删除空部门时一并清理其准入记录。
跨部门调动锁定用户，校验原、新部门的管理范围，并清空本人的角色指派。替换部门准入时回收该部门不再符合准入的指派。任何路径都保护最后有效 SUPER_ADMIN。
根实体version仅处理可选HTTP version冲突，不代替图写互斥；L1/L2缓存键必须包含system+user+权威version，事务内禁止回填。
Redis故障可受限回源，MySQL不可用必须503，不能用旧缓存放行或让注销令牌复活。

== 种子、编号与保密

root显式id=1、subject=rbac-u1，password_hash为UNINITIALIZED；只有该哨兵仍存在时，受控启动从RBAC_BOOTSTRAP_PASSWORD生成哈希，不重置既有口令。不得硬编码公开初始密码。
中心角色SUPER_ADMIN/RBAC_ADMIN/AUDITOR，课程角色teacher/student/admin；所有直接准入明确插入，root的SUPER_ADMIN总部准入必须存在。
除root的中心角色外不自动指派用户；正式员工、选课名单与隐私不进入种子/Git/镜像。对接按code/subject查找，不依赖示例自增ID。

课程teacher API权限仅course:access、audit:read、audit:write、CRS，student仅course:access、audit:write；admin逐项关联全部实际API权限。UI权限单独种子，映射不得变成授权捷径。
目录证据见link:../rbac-contract/src/main/resources/catalog/course-operations.json[课程真实操作]、link:../rbac-contract/src/main/resources/catalog/ui-api-coverage.csv[可审阅覆盖矩阵]。

== 审计存储及验证边界

外部origin=COURSE，内部origin=INTERNAL；外部actor_roles_json仅当前系统有效课程角色码。requestId唯一性及payload_hash绑定来源系统、主体和规范化内容；唯一冲突回滚后再读，不在rollback-only事务继续查询。
外部插入独立事务提交后返回201；本地SUCCESS审计与敏感业务同事务，拒绝事实另行独立事务。
审计无业务FK、不随用户/角色删除；索引为(source_system_code,occurred_at,id)、(source_system_code,actor_id,occurred_at,id)、(source_system_code,object_type,object_id,occurred_at,id)。
只插入的应用约定不是数据库防篡改承诺；跨课程DB与中心DB的HTTP调用不具备分布式原子性。

link:../tools/generate-rbac1-contract.py[生成/静态校验工具]和link:../tools/generate-rbac1-contract-test.py[真实Flyway迁移校验工具]提供独立验证入口；后者只重建专用13306容器内rbac1_schema_contract_test，不碰rbac_test。
工具存在或曾通过不代表双后端当前所有用例通过；本隔离文档任务不执行迁移，真实事务/并发验收见link:test-plan.adoc[测试计划]。

=== 课程内置角色

课程系统初始化时创建 teacher、student、admin，并将各自的默认权限直接绑定到相应角色。升级沿用原有内置角色的 ID、权限、用户指派和部门准入。V7 删除旧身份字段。原自定义角色的权限、指派和已有继承关系继续保留。曾仅通过旧身份字段取得课程资格的自定义角色，需要管理员按实际权限要求重新配置课程角色。迁移不会自动添加继承边。如果旧角色使用了保留角色码却没有对应的旧身份标记，V6 将它改为 legacy-role-{id} 或带唯一后缀的编码，避免该角色意外取得课程资格。
