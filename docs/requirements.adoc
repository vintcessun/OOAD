== 系统定位与范围

权限中心为管理后台和课程项目管理系统提供同一套登录身份。用户可以使用同一账号进入不同系统。各系统分别授予角色和权限，系统之间的授权互不通用。

权限中心管理员维护用户、部门、角色、继承关系、菜单、按钮和 API 操作目录。管理后台据此控制自己的页面与操作。课程系统复用中心登录、请求准入、身份目录和审计服务，继续管理学期、课程、教学班、名单、组队、里程碑、口试和成绩，并按自己的业务关系判断用户能操作哪些对象。权限中心只管理统一身份、权限配置及其审计资料。

本期采用 RBAC1。用户在各系统中可以被直接指派多个角色，角色可以继承同系统其他角色的权限。组织采用一个部门树，每名用户只能归属一个部门。部门同时限定权限中心管理员可管理的人员范围，以及哪个角色可直接指派给本部门用户。部门准入本身不授予角色，也不参与课程对象范围的判定。

本期须交付下列功能、非功能要求和课程交付约束。范围外包括多公司和多租户、部门业务数据范围和仅本人数据规则、职责分离及临时授权、旧版协议兼容、热力图和统计大屏。课程设计的统一身份服务使用约定的课程集成接口，正式接替学校统一身份平台须另行确认。

=== 助教运行检查

. *两系统同集群运行*。权限中心前端、权限中心后端、课程前端和真实课程后端都部署在同一个 Docker Swarm 集群上，两个系统的权限由权限中心管理。检查服务可用，并从浏览器打开两套前端。
. *菜单操作能追溯到后端*。使用具备管理权限的测试账号登录权限中心，从侧栏打开确实调用 API 的菜单，例如用户或角色管理。用同一次操作的追踪标识，在实际运行的后端 Logback 日志中找到对应操作及结果。
. *在真实课程系统验证放行和拒绝*。通过课程工作台或已接入的课程前端完成名单登录，使用合成账号检查一项获准操作和一项无权操作。再用课程拷贝或其他有对象约束的操作，区分中心的系统级准入和课程后端对具体对象的判断。课程前端的菜单与按钮按 <<EXT-06>> 查看，API 结果有独立的联调证据。
. *验证两种实现可切换*。在约定的测试环境中，先用一套后端完成登录、查看授权和课程请求，再切换到另一套重新验证。核对使用同一前端及数据基线，原有账号、配置和审计仍可使用，并记录活动实现及版本。

现场入口与操作见 link:deployment.adoc[部署与切换说明]和 link:swarm-deployment.md[Swarm 部署指南]。健康检查、前端业务流程和课程授权各留相应证据。

=== 教师抽查与项目测试门槛

* *需求与测试*。按需求编号对照测试代码，现场运行前端核对正常操作及异常反馈。代表场景包括登录、注销和撤权，部门调动与角色准入，继承及成环拒绝，菜单和 API 独立授权，真实课程对象级权限，同一审计请求重试及中心写入失败回滚。两套后端对照接口结果和最终业务状态。分页规模场景使用一万条合成用户数据；撤权场景检查两个服务实例在下一次请求中的结果。
* *包图与代表 API*。展示两种后端的包图及其职责、依赖关系。可从继承验环、指派与调动、有效权限计算、课程请求准入、审计幂等、业务与成功审计共同提交中选择有设计差异的 API，对照两版类图、时序图和实际代码。说明为什么分配这些职责，以及对应的 GRASP 原则和实际使用的 JavaEE 技术。
* *覆盖率与复跑*。按项目已配置的门槛复核后端整体行覆盖率至少 70%、分支覆盖率至少 60%，结构化业务服务层和 DDD 应用层的行覆盖率至少 85%。前端纳入覆盖统计的逻辑行覆盖率至少 85%、分支覆盖率至少 80%。报告应能对应源版本和测试范围。覆盖率门槛、运行方式和代表用例见 link:test-plan.adoc[测试计划]、link:requirements-traceability.adoc[需求追踪与验收索引]。

以下三条业务链路可用于现场从页面追到需求、接口与测试。link:oral-review/cross-review.adoc[口试交叉复核]

* “角色指派与撤权”。从“用户管理”指派部门准入的角色，在“角色继承”或“有效权限”核对间接授权；调动用户后，在两个实例用原凭证检查已撤去的角色授权。
* “变更与审计”。提交一次角色状态或授权变更，从“操作审计”查成功事实。用现有故障用例检查审计写入失败时，业务状态和成功审计都未提交。
* “课程登录与授权”。用“教师”身份进入课程系统，分别核对中心准入、课程后端对象规则及有权查询的审计结果。使用同一请求标识补试只应确认同一审计事件。

== 使用者与权限边界

权限中心的管理资格按具体操作判断，组织范围按用户所属部门判断。“权限中心管理员”是具备相应管理授权的用户的统称。需要 `SUPER_ADMIN` 的条目明确写为“权限中心超级管理员”。

[cols="1,3",options="header"]
|===
|使用者 |职责和可操作范围

|权限中心管理员
|在权限中心（`rbac-center`）获得相应管理授权的用户。`RBAC_ADMIN` 是预置的管理角色之一；通过自定义角色获得相应授权的用户也可办理该操作。具备该操作资格的权限中心超级管理员也适用使用该通称的需求。

|权限中心超级管理员
|在权限中心的有效角色中具有内置 `SUPER_ADMIN` 的用户，可由直接指派或有效继承获得。这项资格可满足权限中心受保护管理 API 的常规授权检查。操作还须按各自规则检查会话、系统和入口状态、部门范围、角色准入以及最后一位有效权限中心超级管理员保护。

|根部门的权限中心管理员
|所属部门为根部门，组织管理范围覆盖整棵部门树。维护系统、角色、权限、继承或资源等系统级共享定义，还须具备对应操作资格。属于普通权限中心管理员时，仍受目标系统授权上界约束。

|非根部门的权限中心管理员
|所属部门为非根部门。可按操作授权管理本部门及下级部门的人员、部门、准入和角色指派。维护系统级共享定义须满足根部门资格。

|已登录用户
|查看本人身份与当前系统允许的入口，修改自己的密码或退出。取得管理授权后，可在相应范围内办理该项操作。

|课程管理员、教师、学生
|分别对应课程系统中的有效 `admin`、`teacher`、`student` 角色码。课程身份适用于课程系统。课程系统按课程、教学班和小组等业务关系处理具体操作，课程组长也由课程系统按课程关系判定。

|课程后端
|按集成契约调用统一认证和授权，查询必要的身份和 API 能力，并同步写入及读取课程审计。受信服务调用同时受服务身份与用户授权约束。
|===

“普通权限中心管理员”指拥有相关管理授权、有效角色中没有权限中心内置 `SUPER_ADMIN` 的用户。部门归属与角色授权分开判断。同一位权限中心管理员可以同时具有课程角色，实际使用的角色由本次登录的系统决定。

管理后台登录时选择权限中心。页面上的目标系统选择用于浏览和维护相应系统的角色、权限和资源。切换该选择不会改变已登录的身份或令牌所属系统。进入课程系统时须取得课程系统的登录凭证。

== 业务数据与状态

[cols="1,4",options="header"]
|===
|业务信息 |关键字段和规则

|系统
|系统编码、名称、启用状态。系统编码唯一，用于确定授权目的系统。

|部门
|部门编码、名称、上级部门、启用状态。根部门是管理范围的起点，用户归属树中一个部门。部门按角色清单控制直接指派资格。

|用户
|账号、不可变主体标识、姓名、可选工号或学号、可选联系方式、所属部门和状态。状态为正常、停用或已删除。删除后保留历史账号标识，原账号不得重新用于新用户。

|角色与指派
|角色包括所属系统、系统内唯一的角色编码、名称、说明及启用状态。直接指派关联用户和某系统中的角色。继承关系记录上级角色和被继承角色。

|权限与资源
|权限包括系统、编码、名称、种类和状态。按系统及 UI/API 种类识别权限。菜单和按钮记录层级、显示次序及要求的 UI 权限。API 操作记录操作标识、方法、路径、访问策略及授权条件。

|审计记录
|记录来源系统、发生时间、操作者、操作、对象、结果和适用的追踪标识。敏感变更可附脱敏后的前后值，课程审计附请求标识。同一事件可在操作者停用或删除后继续追溯。
|===

== 功能需求与验收标准

管理动作均以操作者已登录且拥有当前动作所需权限为前提。组织管理范围和目标系统授权上界还须分别满足 <<ROLE-06>>。卡片标题列出需求编号和名称。验收核对操作结果，并在拒绝或故障场景检查业务状态和权限是否保持一致。

=== A. 系统与统一身份

[[ID-01]]
==== ID-01 登记和启停系统

前置条件:: 操作者已登录权限中心。查看系统需要系统查看权限，登记、改名和启停还要求操作者位于根部门并拥有系统管理权限。
功能描述:: 操作者在“系统登记”查看系统编码、名称和状态，通过“登记系统”“编辑系统名称”“停用系统”“启用系统”办理相应业务。
业务规则:: 系统编码全局唯一，登记后保持稳定。新系统登记后为启用状态。角色、权限、资源和审计按系统归属。停用保留配置，暂停该系统的登录和受保护访问。重新启用前检查将恢复的有效权限和受保护角色码是否符合 <<ROLE-06>>。
异常处理:: 重复编码、无权操作、目标系统不存在或重新启用超出授权上界时拒绝请求。
验收标准:: 登记后可查看并修改名称，重复编码提交失败。停用课程系统后，原课程凭证不能访问该系统的受保护入口，已启用的其他系统仍可使用。普通权限中心管理员尝试恢复超过自身上界的授权时，目标系统仍停用。

[[ID-02]]
==== ID-02 按目标系统登录

前置条件:: 用户持有已登记账号的凭据。请求须指明一个已接入的目标系统。
功能描述:: 用户在“登录”输入账号和密码，身份中心核验账号和系统状态，签发仅适用于本次目标系统的会话凭证。权限中心与课程系统可以使用同一套账号。
业务规则:: 同一账号在不同系统具有相同的稳定主体标识。用户须分别取得各系统的凭证。正常账号连续五次凭据校验失败后锁定登录 15 分钟，锁定期间正确密码也不能解除锁定。锁定到期可重试，成功登录清除失败计数和锁定状态。
异常处理:: 错误凭据、锁定、停用或删除的账号均不能登录。未知、停用或多于一个目标系统不能取得凭证。身份服务不可用时须报告失败。
验收标准:: 同一账号分别登录权限中心和课程系统，主体标识相同，凭证目标系统不同。将其中一份凭证用于另一系统的受保护入口时被拒绝。覆盖第五次失败、锁定期提交正确密码、锁定到期以及成功后重新累计失败的情形。

[[ID-03]]
==== ID-03 本人资料、改密与退出

前置条件:: 用户持有当前系统有效的会话凭证。
功能描述:: 用户通过“本人资料”查看基本信息和本人有效权限，在“修改密码”核验原密码并设置新密码，也可主动退出当前会话。
业务规则:: 对接系统的本人身份响应仅提供稳定主体、显示姓名、学工号、当前系统对接协议约定的有效角色码及有效 UI 权限。权限中心的本人页面按自身授权展示本人资料和有效权限。修改密码使该账号此前签发的凭证失效，用户须重新登录。退出成功后，本次凭证的撤销记录持续有效。
异常处理:: 当前会话无效、原密码错误或新密码不符合校验规则时拒绝相关操作。退出未得到服务端成功确认时，界面可以清除本地会话，服务端撤销状态以实际结果为准。
验收标准:: 课程教师通过课程身份响应看到本系统的教师身份和 UI 权限。用错误原密码提交后，原密码仍可使用。用正确原密码完成修改后，此前凭证被拒绝。退出后把同一凭证分别提交给两个实例，两处均拒绝。

[[ID-04]]
==== ID-04 查询、创建和维护用户

前置条件:: 操作者已登录权限中心，拥有相应的用户查看或编辑权限，目标用户或目标部门在其管理子树内。
功能描述:: 操作者在“用户管理”按账号或姓名关键字、部门和状态筛选用户，分页查看结果和用户详情，并办理“创建用户”“编辑资料”“变更状态”和“删除用户”。
业务规则:: 用户有且只有一个所属部门。创建时填写账号、姓名、启用且可管辖的所属部门和初始凭据，可按需填写学工号与电话号码。账号和稳定主体不可经资料编辑改写，状态与部门归属分别通过独立操作维护。停用使账号丧失登录及受保护访问资格，保留角色指派；恢复前检查启用系统中将恢复的有效权限和受保护角色码。逻辑删除回收直接指派，保留历史审计所需身份记录，账号不可恢复或重用。列表先按管理范围和筛选条件确定条目及总数，再稳定分页。
异常处理:: 重复或已删除的账号不得新建；停用部门不能接收新用户。普通资料请求篡改状态、部门或用户名时拒绝。不能恢复超出操作者上界的授权，也不能通过状态变更或删除使最后一位有效权限中心超级管理员失效。
验收标准:: 兄弟部门用户及其数量不进入可管理列表。通过普通资料编辑不能改变部门或状态。停用再恢复后须重新登录，旧凭证被拒绝。恢复超界账号或删除最后一位有效权限中心超级管理员失败，并核对操作前后的账号状态和指派一致。

[[ID-05]]
==== ID-05 调动用户

前置条件:: 操作者具有用户编辑权限，并能管理用户当前部门和目标部门。跨部门时，目标部门须处于启用状态。
功能描述:: 操作者在“用户管理”选择“调动部门”，指定用户新的唯一所属部门。
业务规则:: 跨部门调动与回收该用户在各系统的全部直接角色指派同时生效。目标部门即使准入相同角色，也须按新部门重新指派。重复提交同一部门时保留指派。共享角色定义、继承关系及其他用户的指派保持原状。
异常处理:: 调入停用部门、两部门任一超出管理范围、提交的资料版本已变更或调动将使最后一位有效权限中心超级管理员失效时，整次调动失败，原部门和指派保留。
验收标准:: 让一个在两个系统拥有直接角色的用户调入同样准入这些角色的部门，确认用户归属更新、两套指派清空、原凭证不能再凭这些角色取得权限，其余用户的同角色指派仍有效。提交同一部门仍保留指派，拒绝场景不会只改归属或只撤旧角色。

[[ID-06]]
==== ID-06 分系统指派角色

前置条件:: 操作者具有对应的用户查看或指派管理权限，目标用户在管理子树内。新增指派时用户、当前部门、目标角色及其系统须处于可用状态。
功能描述:: 操作者在用户详情的“角色指派”按目标系统查看直接指派，使用“指派角色”或“撤销指派”管理具体关系。
业务规则:: 用户可在多个系统分别持有多个直接角色。指派依据用户当前的实际部门，角色须符合部门准入 <<ROLE-05>> 和操作者在目标系统的授权上界 <<ROLE-06>>。撤销根据操作者当前权限及管理范围办理，且被撤销的指派必须属于目标用户。
异常处理:: 重复指派、不符合准入、角色或系统停用、超出授权上界及试图撤销其他用户的指派时拒绝相应请求。
验收标准:: 为用户添加课程角色后，课程系统的直接指派增加，权限中心的指派保持原状。提交别人的指派标识无法撤销。停用部门内既有指派可由有相应授权的权限中心管理员查看和撤销，新增指派被拒绝。

[[ID-07]]
==== ID-07 稳定身份与凭据保护

前置条件:: 初始凭据由有相应授权的权限中心管理员在开户时设置，系统引导凭据由受控配置提供。
功能描述:: 身份中心为每个用户分配长期稳定的主体标识，并验证登录凭据。经授权的对接系统按稳定主体关联本地业务身份。
业务规则:: 稳定主体独立于账号显示资料和内部数字编号。调动部门、改名、改密或再次登录时继续使用同一主体。密码只以用于验证的单向形式保存，系统没有固定公开的管理员密码。个人资料、目录数据和响应按契约输出允许字段，凭据保密要求见 <<NFR-06>>。
异常处理:: 错误密码和不存在账号等凭据验证失败使用通用失败反馈，并避免披露密码、摘要或账号是否存在。
验收标准:: 修改用户名称、所属部门及密码后，课程可以按原主体关联既有记录。从本人、目录和管理响应及日志中无法读出密码、密码摘要、完整会话凭证或服务凭据。

=== B. 部门与直属成员管理

[[ORG-01]]
==== ORG-01 建立和维护部门树

前置条件:: 已存在根部门。操作者拥有部门查看或编辑权限，目标部门位于其管理子树内。
功能描述:: 操作者在“部门准入”浏览部门树及选中部门的详情，使用“创建部门”建立下级部门，使用“编辑部门”修改名称。
业务规则:: 部门树只有一个根部门。新建部门须指定一个启用的上级部门，并填写唯一部门编码和名称，新部门初始启用。一般编辑只修改名称。部门树的查看范围由操作者当前所属部门确定，根部门的权限中心管理员在有查看权限时可浏览整棵树。课程目录的查询规则见 <<EXT-01>>。
异常处理:: 重复部门编码、试图创建第二个根部门、上级部门不存在或停用、目标越出管理范围，或通过名称编辑更改其他字段时拒绝相应请求。
验收标准:: 以非根部门且有相应授权的权限中心管理员进入“部门准入”，确认可查看当前部门及下级部门。在启用上级下成功创建子部门并修改名称。兄弟部门不可见，越权改名与在停用部门下新增子部门均失败。

[[ORG-02]]
==== ORG-02 启用和停用部门

前置条件:: 操作者有独立的部门启停权限，目标部门位于其管理子树内。
功能描述:: 操作者在“部门准入”选中部门，使用“停用部门”暂停接纳，或使用“启用部门”恢复接纳。
业务规则:: 只有无子部门的非根部门可以停用。停用保留成员所属部门、账号状态和既有指派。课程部门目录隐藏该部门，也不提供该部门的直属成员列表。停用期间禁止新建或迁入成员、新建子部门及新增指派。中心管理端允许有相应权限的人员查看、改名、维护准入、迁出成员和撤销指派。重复提交已经处于的状态时，返回当前状态。
异常处理:: 停用根部门、停用仍有子部门的节点、没有启停权限或超出管理子树时拒绝，部门状态保持原样。
验收标准:: 停用有成员的叶部门后，确认既有用户仍可登录并使用已有有效权限，课程目录不再提供该部门。新增成员、迁入和新增指派被拒绝，按权限办理迁出和撤销仍可成功。重新启用后该部门恢复接纳。仅拥有部门编辑权限的操作者不能启停。

[[ORG-03]]
==== ORG-03 删除部门

前置条件:: 操作者拥有独立的部门删除权限，目标部门位于其管理子树内。
功能描述:: 操作者在“部门准入”选中部门并执行“删除”。
业务规则:: 只有非根部门且没有子部门和所属成员记录时才可删除。停用不会使部门自动满足删除条件。删除部门及其准入关系同时生效。
异常处理:: 目标为根部门、存在下级部门、仍关联任何成员记录或不满足权限和管理范围时拒绝。
验收标准:: 删除可管辖的空叶部门后，部门树和该部门的准入关系均不再包含该项。对有下级或成员记录的部门、根部门以及无删除权限的请求分别检查拒绝结果，部门及准入关系继续可查。

[[ORG-04]]
==== ORG-04 维护部门可指派角色

前置条件:: 操作者在管理子树内行使部门权限。查看准入使用部门查看权限，保存准入使用部门编辑权限。
功能描述:: 操作者在“部门准入”按系统查看配置并使用“保存准入”更新选中的部门允许直接指派的角色。
业务规则:: 准入清单管理的是用户与角色建立直接指派的资格，新增准入不会自动赋予角色。管理页面保存当前系统的变更时保留其他系统的选择；服务端将收到的整份准入作为新配置，并同时回收该部门用户中不再满足准入的直接指派。其他部门用户、共享角色及其继承关系不受影响。普通权限中心管理员可原样保留停用系统的准入，变更停用系统准入须由权限中心超级管理员执行。启用系统中保留在新清单的角色仍须符合操作者的授权上界。
异常处理:: 角色不存在、超出管理范围或授权上界，普通权限中心管理员新增或移除停用系统的准入时拒绝，现有配置和指派保持原样。最后一位有效权限中心超级管理员保护见 <<ROLE-07>>。
验收标准:: 在允许多个系统角色的部门中，移除一个角色的准入后，该部门对应用户的直接指派被回收，其他部门的同角色指派与其他系统未变更的准入保持有效。普通权限中心管理员原样保留停用系统准入并保存启用系统的变更可以成功，改动停用系统的准入则被拒绝。

=== C. 角色、继承与授权边界

[[ROLE-01]]
==== ROLE-01 创建、维护和启停角色

前置条件:: 操作者已登录权限中心并选择已登记的目标系统；查看需要角色查询权限，创建、编辑或启停还要求根部门管理资格和相应操作权限。
功能描述:: 操作者在“角色管理”按名称、编码或状态检索并分页查看角色。通过“创建角色”填写编码、名称及可选说明。在详情中使用“编辑资料”或“变更角色状态”分别维护资料和启停状态。
业务规则:: 角色归属一个系统，同一系统内编码唯一。创建的角色初始启用且没有直接权限。启停有独立权限，普通编辑只允许修改名称和说明，可携带版本防止覆盖他人的更新。启用会恢复符合当前规则的授权，须按 <<ROLE-06>> 校验。
异常处理:: 编码重复、名称无效、目标不存在、请求超出管理权限或编辑版本过时均应拒绝。拒绝后原角色资料和状态保持原值。
验收标准:: 在两个系统中分别创建相同编码的角色成功，同系统再次创建被拒绝。只有角色编辑权限的普通权限中心管理员可以改名，启停请求会被拒绝。两名有编辑授权的操作者打开同一详情，一人更新后，另一人持旧版本提交不会覆盖新资料。

[[ROLE-02]]
==== ROLE-02 配置直接权限并查询继承来源

前置条件:: 目标角色存在，操作者有角色查询权限。保存直接权限要求角色编辑权限和根部门管理资格。
功能描述:: 角色详情的“直接权限”用于勾选角色本身的授权，并通过“保存直接权限”提交。检索或跨页时保留已选项。“继承来源与有效权限”展示有效权限、授予角色和可达的继承路径。
业务规则:: 每次保存原子替换角色的整个直接权限集合，空集合代表清空。只接受同系统权限。角色本身和可达启用角色贡献各自启用的权限；按种类和编码去重，同码的 UI 与 API 权限分别计入。保留直接来源和每条有效继承路径，继承所得权限不写入直接权限集合。
异常处理:: 引用不存在或跨系统的权限、修改后的授权超出 <<ROLE-06>> 的上界，或变更无法完整保存时，拒绝整次替换，保留原集合。
验收标准:: 设置 A→B、A→C、B→D、C→D，且权限 P 由 D 直接持有。查看 A 时，P 在有效列表出现一次，分别给出经 B 和经 C 到 D 的来源。清空 A 的直接权限后，仍能继承 P。两种类别同码时，来源归属正确。

[[ROLE-03]]
==== ROLE-03 添加和移除角色继承

前置条件:: 操作者选择目标系统，具有角色编辑权限和根部门管理资格，两端角色均已建立。
功能描述:: 在“角色继承”中查看角色、边和路径，使用“添加继承关系”选择“高级角色”和“被继承角色”，使用“移除关系”删除指定边。
业务规则:: 箭头 A→B 表示 A 继承 B 的有效授权。允许一个角色继承多个下级，也允许多个上级继承同一角色。继承可传递，且每个角色在图中只有一个节点。继承关系的每次修改须保证提交后的同系统图无环，并重新计算受影响的有效授权。
异常处理:: 自继承、重复边、跨系统边、将成环的边、移除不存在的关系以及授权超出上界的操作应分别拒绝。成环请求不改变此前已保存的关系。
验收标准:: A→B→C 可令 A 继承 C，菱形结构能显示两条路径。相反的两条边由并发请求添加时，一次成功、一次被拒绝，最终仅保留成功请求对应的方向。移除唯一继承路径后，依赖该路径的授权失效。

[[ROLE-04]]
==== ROLE-04 限制跨系统和停用角色的传播

前置条件:: 已为同一系统配置角色和继承关系。操作者具备查看配置或变更角色状态所需权限。
功能描述:: 在“角色继承”查看角色状态及路径，在角色详情检查有效权限随启停的变化。仍可查询停用的配置及其关系。
业务规则:: 继承只在本系统内计算。停用角色不提供直接权限，也不能作为到下级角色的有效路径。其他启用的可达路径继续生效。目标系统停用时，获得管理权限的操作者可查看启用角色及权限的配置闭包，实际访问和用户在线有效授权受系统状态约束。
异常处理:: 跨系统建边被拒绝。若系统或角色停用使某条授权路径失效，使用此前会话或页面结果也不能继续获得该授权。
验收标准:: 在两路菱形中停用一路的中间角色，经停用角色的来源消失。只经该路的权限被收回，另一有效路径的权限保留。停用整个系统后，管理配置视图仍可查询，实际访问拒绝。

[[ROLE-05]]
==== ROLE-05 按用户当前部门准入指派

前置条件:: 操作者具有指派管理权限，且用户在操作者部门子树内。新增指派要求用户、所属部门、目标系统及角色均处于可用状态。
功能描述:: 在“用户管理”打开用户详情的“角色指派”，按目标系统选择“可指派角色”，使用“指派角色”或“撤销指派”维护已有关系。
业务规则:: 后端依据用户当前所属部门的准入清单重新校验新增请求，并执行 <<ROLE-06>> 的授权上界检查。权限中心超级管理员也须符合部门准入。部门准入约束直接指派，继承仍按目标系统的角色图计算。停用部门保留原指派并允许撤销，停止接纳新指派。跨部门调动按 <<ID-05>> 处理。
异常处理:: 部门未准入、用户或部门状态不允许、角色或系统停用、重复指派、超出管理范围或授权上界时拒绝。撤销请求中的指派不存在或不属于该用户时，应拒绝。
验收标准:: 部门只准入 A 并配置 A→B。指派 A 后，用户取得 B 的有效授权；尝试直接指派 B 时，即使操作者为权限中心超级管理员也应拒绝。撤销 A 后，B 只经 A 获得的授权一并失效。

[[ROLE-06]]
==== ROLE-06 限定管理范围和授权上界

前置条件:: 操作者已通过中心身份及本次管理操作的权限检查。维护系统级共享定义还要求操作者隶属根部门。
功能描述:: 对组织管理、指派及各项会新增或恢复有效授权的操作，按操作者范围和目标系统核查可变更的对象与授权。
业务规则:: 人员、部门、准入和指派操作以操作者本部门子树为边界。普通权限中心管理员的授权上界取变更前在目标系统已有的有效权限和受保护角色码。受保护角色码包括 `admin`、`teacher`、`student`，以及目标系统受保护 API 声明的所需角色码。创建使用受保护角色码的角色、指派角色、替换直接权限、添加继承边和恢复角色、账号或系统时须检查将生效的授权。改动角色时还须检查自身及受影响的全部上级角色。普通权限中心管理员不能构建直接或间接取得权限中心超级管理员能力的路径，包含停用节点的潜在路径也受此限制。
异常处理:: 超出子树、缺少根部门资格或目标系统授权上界不足时拒绝。普通权限中心管理员不得对停用系统新增角色授权，重新启用须检查即将恢复的权限；失败不得保留任何部分变更。
验收标准:: 普通权限中心管理员即使有管理入口授权，缺少目标课程系统的审核权限时，直接或经下级角色间接授予该权限均失败。尝试通过恢复停用账号或系统绕过上界也应失败。非根部门的权限中心管理员能在本子树内办理获准的操作。编辑兄弟部门用户或修改共享角色的请求被拒绝。

[[ROLE-07]]
==== ROLE-07 删除角色与保护最后一位有效权限中心超级管理员

前置条件:: 操作者有角色编辑权限和根部门管理资格，目标角色存在并满足删除条件。
功能描述:: 在“角色管理”的列表或详情选择并确认删除角色。删除成功后回到当前系统角色列表，相关指派和历史审计可按各自权限核对。
业务规则:: 删除角色时一并清理用户直接指派、角色直接权限、双向继承关系和部门准入，保留历史审计。角色、用户、系统、准入或指派变更后，仍须至少有一名活动用户归属根部门，根部门准入 `SUPER_ADMIN`，且该用户在启用的权限中心拥有有效的 `SUPER_ADMIN`。
异常处理:: 目标不存在、超出管理权限或变更会使最后一位有效权限中心超级管理员失效时拒绝。删除及关联清理须共同提交；保护检查或成功审计失败时整次回滚。
验收标准:: 删除普通角色后，从角色列表、用户角色指派、继承图、部门准入和有效权限核对清理，历史仍可查询。若停用、调动、删除账号或撤销指派会使最后一位有效权限中心超级管理员失效，相关请求被拒绝，原状态和关联保留。有另一名符合上述条件的权限中心超级管理员时，按其余规则办理。

[[ROLE-08]]
==== ROLE-08 查看用户在指定系统的权限

前置条件:: 操作者有权限中心的用户权限详情查询资格，被查用户在其管理子树内，已选择目标系统。
功能描述:: 在“用户管理”打开用户详情的“有效权限”，查看当前目标系统中的直接角色、有效角色、UI/API 权限及来源。切换系统或重试时重新取得相应详情。
业务规则:: 详情只显示所选系统的授权。已指派角色、实际生效的角色和权限须能区分。查询停用目标系统返回空的有效授权，查询者自身会话继续有效。读取失败时标明失败并允许重试，不能继续把上一次结果作为当前权限。
异常处理:: 目标系统或用户不存在、操作者未获相应查询权、用户范围不符时给出相应结果。目标停用与操作者认证失败须区分。
验收标准:: 同一用户在权限中心和课程系统拥有不同角色时，两次查询各自显示正确角色与来源。目标系统停用后，有效结果为空。范围外账号不能代查，切换系统或重试也不残留另一目标的旧结果。

=== D. 菜单、按钮、API 与授权检查

[[RES-01]]
==== RES-01 管理权限、菜单和按钮

前置条件:: 已选择目标系统，操作者有相应目录或资源查询权限。维护操作要求根部门管理资格和对应管理权限。
功能描述:: 在“权限目录”按名称、编码及种类查找权限，可使用“创建权限”及“启用”或“停用”。在“菜单与按钮”使用“创建资源”维护各系统的入口、上下级和显示次序。
业务规则:: 权限按系统、种类和编码识别，停用权限不再计入有效授权。菜单和按钮是 UI 资源的两种类型。按钮须属于菜单并配置自己的 UI 权限。菜单可见时，只有同时具备对应按钮权限的用户取得该操作入口。
异常处理:: 同系统同种类重复编码、错误权限引用或资源配置不合法时拒绝，说明对应冲突，原配置保留。
验收标准:: 同一系统可分别设置同码的 UI 与 API 权限。只有菜单权限的用户能进入该页面，但看不到未授权按钮。授予其他系统的同码 UI 权限后，本系统的按钮仍不可用。

[[RES-02]]
==== RES-02 登记 API 操作及访问策略

前置条件:: 目标系统已登记，操作者有 API 目录查询权限。新增或修改操作要求根部门管理资格和资源管理权限。
功能描述:: 在“API 操作”按操作标识或路径检索。通过“登记 API 操作”或“编辑”维护操作标识、HTTP 方法和路径、访问策略、准入条件和启用状态。
业务规则:: 同一系统内操作标识及方法与路径的组合分别唯一。公开操作无须身份，认证操作要求有效本系统身份，受保护操作要求有效本系统身份及登记条件。受保护操作至少设 API 权限或当前系统的所需角色码之一，两项同时设置时都须满足。一个 API 权限可供多个操作复用，停用操作不再放行。条件变更按 <<ROLE-06>> 检查授权上界。
异常处理:: 引用其他系统权限、用 UI 权限作 API 条件、重复登记或给受保护操作留空准入条件，均应拒绝。固定中心操作另受 <<RES-04>> 约束。
验收标准:: 对同时要求教师身份和某 API 权限的操作，分别准备仅有身份、仅有权限和同时拥有两者的账号，只有第三个账号通过该操作的中心准入。操作停用后，相同账号也不能通过。

[[RES-03]]
==== RES-03 维护 UI 与 API 对照关系

前置条件:: UI 资源和 API 操作均已登记于同一目标系统。操作者具有资源查询权限；保存映射还要求根部门管理资格及资源编辑权限。
功能描述:: 在“UI ↔ API 映射”选择菜单或按钮，检索需关联的 API，查看“待保存变更”和“覆盖报告”。可通过“保存映射”提交对照关系。
业务规则:: 一个菜单或按钮可关联多个 API，一个 API 也可被多个资源引用。保存时整体替换目标系统的映射集合，空集合允许清除现有映射。映射用于追踪页面与操作的关系与覆盖情况，UI 与 API 各自按实际授权规则决定访问。
异常处理:: 引用不存在、跨系统或不合法的对象时，拒绝整次保存并保留原映射。检索或分页变化不应丢失待保存选择。
验收标准:: 将同一操作关联两个按钮，并给其中一个按钮再关联另一操作。保存后覆盖报告和原有映射与选择一致。用户只有按钮权限时，直接调用关联 API 仍拒绝；移除映射后，已经独立授予的 API 权限仍可按其规则使用。

[[RES-04]]
==== RES-04 核对受保护操作覆盖

前置条件:: 管理服务具备当前共享接口契约、实际接入的路由和对应操作目录。
功能描述:: 对照实际入口和操作登记，双向核查中心受保护入口都有对应的已启用登记，固定登记也都有约定的实际入口。
业务规则:: 固定中心操作的操作标识、方法、路径、访问策略与准入条件须与共享契约一致。中心运行时默认拒绝未登记或无法识别的受保护操作。课程入口按 <<EXT-03>> 和 <<EXT-04>> 登记、解析和鉴权。编辑目录元数据不会创建实际业务路由。
异常处理:: 固定中心操作的登记与契约不一致时拒绝保存或拒绝启用不一致的服务配置。未知或歧义的受保护路由不得获得许可。
验收标准:: 以去掉固定操作或加入无实际入口的中心登记验证双向检查。试图把固定管理操作改为公开、修改路径、停用或削弱其准入条件时被拒绝，原实际路由仍按契约工作。

[[RES-05]]
==== RES-05 保护资源树和映射的完整性

前置条件:: 操作者在“菜单与按钮”选择目标系统并具有资源管理权限及根部门管理资格。
功能描述:: 使用“编辑”调整资源层级或 UI 权限，使用“新增子资源”将菜单或按钮挂到适用的上级，使用“删除”移除可删除的资源。
业务规则:: 上级必须是同系统菜单，按钮不能作上级。资源不得成为自己的上级或下级。资源有子节点或仍被映射引用时不能删除。重新绑定按钮的 UI 权限时，按钮仍对应原资源和未更改的 API 映射，显示资格按新绑定生效。
异常处理:: 上级不存在、跨系统、类型错误、形成环、资源正在使用或引用了不适用的权限时拒绝。拒绝后资源树与映射保持一致。
验收标准:: 尝试将父菜单移到自己的子菜单下失败。保留子节点或映射时不能删除父资源，清理引用后可以删除。替换按钮权限后，原 API 映射保留，拥有新 UI 权限的用户能够看到该按钮。

[[RES-06]]
==== RES-06 按当前授权显示入口并拦截直接访问

前置条件:: 用户以有效会话访问对应系统，前端能够取得该系统的当前 UI 权限及适用的资源配置。
功能描述:: 按有效授权显示导航菜单和页面按钮，刷新权限后同步更新当前页面、导航和按钮；直接打开受保护地址使用相同判定。
业务规则:: 资源停用、其祖先入口被阻断或用户缺少对应 UI 权限时，相关入口不能被使用。撤回后的权限和菜单须以新结果替换旧结果。API 调用由服务端根据自身契约和当前权限独立决定。
异常处理:: 未登录时进入登录，明确无权时显示禁止访问。刷新无法确认权限时拦截受保护访问，提供可重试的失败反馈；旧页面或旧权限不能用于继续操作。
验收标准:: 停用一个菜单或撤回其权限后，当前页、正常地址和带大小写或尾斜杠变体的地址均无法绕过限制。有 UI 无 API 时直接请求被拒绝，有 API 无 UI 时相关菜单和按钮不出现。模拟权限刷新故障时验证拦截及重试。

[[AUTHZ-01]]
==== AUTHZ-01 检查并解释授权决定

前置条件:: 操作者登录权限中心并有授权检查权限。检查可以针对本人或指定用户，代查其他用户须符合本部门子树管理范围。
功能描述:: 在“鉴权解释”选择目标系统和 UI 或 API 类型，输入相应的权限码或操作标识。使用“检查权限”取得判定，使用“解释来源”查看判定步骤和目标有效授权的来源。
业务规则:: 按目标系统的可信权限事实判断，UI 检查权限码，API 检查已登记操作及其访问策略。无法访问的目标返回相应的拒绝原因。对停用用户或停用系统，显示目标拒绝和空的有效结果，调用者的有效会话继续使用。两套后端应按同一权限与组织范围规则处理，并为一次解释返回相互一致的判定、原因和来源。
异常处理:: 目标不存在、两类标识误传或超出契约长度、操作者未认证或无查询资格、服务不可用时分别返回相应错误。合法查询的“拒绝访问”结果与“无权执行此查询”区分。
验收标准:: 验证本人和子树内用户的允许、正常拒绝、停用及多来源解释。子树外代查被拒绝，未知目标和非法输入给出对应错误。用具备授权检查权限的非种子角色验证两套后端的代查条件一致。权限发生并发变更时，单次返回不得混用新旧授权。

=== E. 课程系统接入

[[EXT-01]]
==== EXT-01 提供课程统一身份和目录接口

前置条件:: 课程系统已登记并启用。课程“登录身份”区分“学生”“教师”“管理员”。学生、教师在课程系统有可核验的名单记录。课程目录调用者持有效课程凭证，拥有课程系统的有效 `admin` 角色码和教师管理 API 权限 `TEC`。
功能描述:: 中心按 link:course-integration-contract.adoc[课程集成合同]提供登录、退出、本人信息、UI 权限判断、API 操作判断、部门展开、直属成员查询及按稳定主体单查八项能力。学生从课程入口输入“学号”，教师输入“工号”。课程系统核验本地名单并调用统一认证，确认或绑定稳定主体。课程管理员通过统一身份入口登录课程系统。
业务规则:: 部门查询从根部门或指定上级展开启用的部门，可按部门名称或编码搜索。直属成员可按姓名、工号或学号搜索，只在指定启用部门中返回状态正常的直属成员。按稳定主体单查只返回正常账号的最小字段。
异常处理:: 学生或教师无法通过名单核验或统一认证时，本次登录失败。未认证的目录请求返回 401，使用非课程凭证或缺少课程系统有效 `admin` 角色码或 `TEC` 的请求返回 403。不存在或已停用的部门不能展开或列成员。不存在、已停用或已删除的用户不能按主体查出。
验收标准:: 同一课程人员重复登录，课程记录仍关联同一稳定主体。持有效课程凭证且同时具有课程系统有效 `admin` 角色码和 `TEC` 的用户可浏览、搜索并分页查询目录。分别验证普通教师、非课程凭证、停用部门、停用用户均不能取得相应目录数据。

[[EXT-02]]
==== EXT-02 提供课程审计写入和查询

前置条件:: 课程后端持有可信服务凭据，且调用关联到持有效课程凭证的用户。该用户具有与写入或查询相应的审计 API 权限。
功能描述:: 中心提供课程审计写入和查询接口。课程后端可提交成绩、分组、里程碑或名单的变更事实，也可为用户查询其可见范围内的事件。
业务规则:: 用户身份、可信服务身份和相应的审计 API 权限须同时满足。课程前端经课程后端取得符合课程业务范围的查询结果，服务凭据由后端持有。写入确认遵守 <<AUD-01>>，查询与分页遵守 <<AUD-02>>。
异常处理:: 未认证时返回 401。服务身份验证失败或用户缺少相应权限时返回 403。写入未得到中心确认时按 <<EXT-07>> 反馈，查询失败应与空结果区分。
验收标准:: 分别移除有效用户凭证、可信服务凭据、写入或查询权限，请求应被拒绝且不得新增或返回审计事实。提交并确认一条约定事件后，有权用户可经课程端查询到该记录。

[[EXT-03]]
==== EXT-03 使用课程系统的真实操作契约

前置条件:: 课程接入采用已确定版本的教师课程 OpenAPI，课程操作目录与对接版本一致。
功能描述:: 根据对接契约登记课程操作的操作标识、方法、路径和全局授权条件。中心提供方操作由中心处理，课程业务操作由课程后端处理。对接版本变化时核对新增、删除和变更操作的覆盖与授权条件。
业务规则:: 登录、身份目录和审计等中心提供方操作，与课程业务操作分别对应其契约入口。契约明确公开的课程登录应交给课程后端核验本地名单。其他受保护业务操作应符合 <<EXT-04>>，全局准入后继续执行 <<EXT-05>>。
异常处理:: 无法识别、存在歧义或与登记不符的课程业务路由不得转发。发现契约版本与登记不一致时，应明确缺失或变更的操作，以便核对覆盖与授权条件。
验收标准:: 逐项对照课程契约和登记目录，验证操作标识、方法、路径和授权条件。按约定发起匿名课程登录能由课程后端处理。未登记的课程业务请求没有被转发。

[[EXT-04]]
==== EXT-04 对课程请求执行系统级准入

前置条件:: 请求命中接入范围内的受保护课程操作。权限中心保存当前的课程操作登记及课程上游配置。
功能描述:: 权限中心对受保护的课程请求执行系统级准入，通过后向已配置的课程后端转发。
业务规则:: 用实际 HTTP 方法和路径识别操作，根据验证后的凭证确定用户与课程受众，核查用户、系统和操作状态，并检查当前操作的全局授权条件。客户端提供的目标地址、身份或操作标识均不能改变判定依据与转发目标。
异常处理:: 凭证无效、受众不符、缺少权限、操作未登记或停用时均不得转发。授权服务无法给出可靠判断时按服务不可用处理。
验收标准:: 获准的课程请求到达真实课程后端。对跨系统凭证、无权限、未登记路由以及伪造身份或操作提示的请求，核对权限中心拒绝且课程后端未收到该请求。

[[EXT-05]]
==== EXT-05 保留课程对象级授权和私有身份查询

前置条件:: 课程业务请求已通过全局准入。调用私有身份接口的课程后端持有可信服务凭据，并传递当前用户的有效凭证。
功能描述:: 课程后端继续依课程、教学班、小组和人员关系判断具体对象是否可操作。中心提供当前系统的有效 API 权限和课程协议约定的有效角色码，以及按稳定主体查询最小身份信息的私有入口。
业务规则:: 两项私有接口均验证用户和服务身份，按已验证的目标系统取值。按稳定主体查询还要求课程系统的有效 `admin` 角色码和 `TEC`，只返回稳定主体、姓名及工号或学号。课程拷贝的全局身份条件为教师，课程后端另行判定课程组长与非组长应有的课程拷贝权限 CC。
异常处理:: 公开入口不得访问私有身份接口，服务身份不可信或用户缺少调用资格时拒绝。按主体查询不到正常账号时返回 404。课程后端作出的对象级拒绝仍须传给调用者。
验收标准:: 用具备教师身份但无 CC 的课程组长、具备 CC 的非组长、无 CC 的非组长分别尝试课程拷贝，前两种按对象规则可以成功，最后一种在课程后端被拒绝。公开入口或缺少任一身份凭据时无法取得私有身份接口，合法身份查询仅返回约定字段。

[[EXT-06]]
==== EXT-06 隔离两套系统的用户界面权限

前置条件:: 用户已登录指定系统，所用凭证仅关联当前系统。两套系统已分别配置各自的 UI 资源和授权。
功能描述:: 根据当前系统的有效 UI 权限为用户提供菜单、按钮和本人信息。
业务规则:: 公开本人信息中的角色和权限仅包含当前系统对接协议约定的有效角色码和有效 UI 权限。课程后端通过可信私有身份接口取得 API 能力。菜单或按钮的显示仍遵循 <<RES-06>>，受保护操作由各自的后端授权。
异常处理:: 凭证不适用于另一系统的受保护入口。无效或已撤销的凭证不得读取有效本人信息或使用受保护入口。
验收标准:: 同一主体分别登录两系统时只看到各自获准的入口。对选定的课程菜单和业务按钮分别授予与撤销 UI 权限，核对其显示随授权变化，后端仍独立作出 API 判定。只持有课程角色的账号不能获得中心管理权限。检查课程公开本人信息，确认其中无完整 API 权限清单。

[[EXT-07]]
==== EXT-07 处理课程鉴权和审计联调故障

前置条件:: 课程业务请求已登记。其中需要审计的变更归属 <<EXT-02>> 约定的事件，课程后端为同一事件使用固定请求标识。
功能描述:: 鉴权可确认时按结果处理业务请求。需要审计的课程业务提交后，在返回确认结果前向中心同步写入审计事实。
业务规则:: 传输故障时用原请求标识最多补试一次。中心只在审计记录提交后确认，并按 <<AUD-01>> 处理重放。这个重试只针对审计写入，课程业务与中心审计分属不同事务。
异常处理:: 撤权后下一次受保护请求应被拒绝。鉴权无法确认时不得继续转发。审计经过有限重试仍未确认时返回 503 `AUDIT_UNCONFIRMED`，反馈“业务可能已提交，审计未确认”，调用者应能区分该状态与业务未执行或被拒绝。
验收标准:: 先确认课程操作可用，再撤权并验证下一次请求被拒绝。模拟中心已保存而首次响应丢失，原标识补试应返回同一记录。持续无法确认时返回 503，并核对可能已提交的课程业务与未确认审计各自状态，无第二次业务写入。

=== F. 审计与运行追踪

[[AUD-01]]
==== AUD-01 幂等写入课程审计

前置条件:: 课程后端满足 <<EXT-02>> 的写入条件，并提供有效的事件数据与唯一的请求标识。
功能描述:: 对同一课程审计事件执行持久化，允许调用方使用原请求标识安全补试。
业务规则:: 来源系统和操作者来自经验证的身份。请求标识全局唯一，绑定来源系统、稳定主体和规范化业务内容。三者一致时，同一标识的串行或并发请求返回同一条记录。审计记录提交后才可返回 HTTP 201。
异常处理:: 同一请求标识换内容、主体或来源系统时返回 400 `AUDIT_DUPLICATE_CONFLICT`，不返回旧记录，不改变旧事件。审计尚未提交或持久化失败时不得返回成功。
验收标准:: 首次有效请求产生一条审计记录。串行或并发重放返回相同记录标识且持久数据只有一条。分别变更内容、主体或来源系统后重放，原记录和查询范围均保持原状。

[[AUD-02]]
==== AUD-02 在授权范围内查询审计

前置条件:: 中心调用者具有审计查看权限。经管理页面查询时，还须具备“操作审计”的 UI 访问资格。外部课程查询满足 <<EXT-02>> 的查询条件。
功能描述:: 操作者在“操作审计”中选择授权系统，按操作者、操作者 ID、目标或起止时间筛选、翻页并打开“审计详情”。课程接口在当前课程系统内查询四类外部事件，课程端继续按自身课程、教学班等业务范围裁剪结果。
业务规则:: 先按授权范围和查询条件过滤，再计算总数和分页。排序按时间降序，同一时间以记录标识降序排列。起止时间均包含边界。管理页面按界面标注的时区输入和显示时间，变更筛选或目标系统后从第一页查询，切换目标系统时清空旧详情。
异常处理:: 无权时拒绝读取。起始晚于结束、页码无效或超出分页限制时拒绝查询。正常空结果显示“无匹配审计记录”，故障时应提示可重试。
验收标准:: 用包含其他系统、中心管理事件及课程范围外事件的数据集测试分页，总数和页面仅包含应见事件。以某条记录发生时间作为相同起止点仍能查到该记录。切换目标系统后不显示旧详情，空结果与查询失败有不同反馈。

[[AUD-03]]
==== AUD-03 记录关键变更与安全拒绝

前置条件:: 用户发起审计范围内的身份、管理或课程操作，或触发纳入记录范围的安全拒绝。
功能描述:: 保存可通过“操作审计”或约定的课程查询入口追踪的业务事实。涵盖登录与退出结果、系统和组织状态变更、人员调动、角色指派与撤销、角色继承和权限配置变更，以及约定的四类课程事件。
业务规则:: 已确认的成功和纳入审计范围的拒绝分别记录。关联实际操作者、时间和对象。拒绝事实独立于被拒绝的业务操作，业务回滚不应删除已确认的安全拒绝记录。
异常处理:: 有记录要求的敏感请求被拒后，只留下可核对的拒绝事实，不产生业务变更或相应的成功审计。敏感变更或其成功审计保存失败的情况遵照 <<AUD-05>>。
验收标准:: 撤销一次有效角色指派，在“审计详情”中可核对操作者与目标。发起一次纳入审计范围的越权指派，请求被拒，指派不变且无成功记录，可查询对应的拒绝事实。

[[AUD-04]]
==== AUD-04 关联运行日志

前置条件:: 权限中心接收到需要排查的请求，并启用课程交付要求的分层运行日志。
功能描述:: 提供可关联请求入口、业务处理和数据访问记录的追踪标识，支持从一次管理操作定位对应的运行日志。
业务规则:: 对实际经过的应用层次记录操作、结果、耗时，出现异常时记录异常类别。日志遵守 <<NFR-06>>。审计查询继续从正式审计记录提供业务事实。
异常处理:: 请求失败时日志应能关联相应的失败结果和异常类别，避免暴露参数、响应、异常原文或凭据。运行日志中的方法完成不能用来确认业务数据已提交。
验收标准:: 执行菜单切换、指派、撤销或鉴权解释后，能在后端日志中找到与操作对应的记录。对指派、撤销等实际经过各层的请求，用同一追踪标识串起各层日志并检查无敏感信息。

[[AUD-05]]
==== AUD-05 保证中心敏感变更与成功审计一致

前置条件:: 有权操作者发起须同步保存成功审计的中心敏感管理变更。
功能描述:: 将管理变更和相应的成功审计共同提交。提交后业务结果与成功记录均可查询。
业务规则:: 业务数据、该变更推进的授权版本和成功审计应处于同一事务。纳入范围的拒绝记录独立保留。课程跨系统审计按 <<EXT-07>> 执行。
异常处理:: 业务更新或成功审计保存失败时，对应业务数据、授权版本和成功审计全部回滚，向操作者返回失败。
验收标准:: 在角色授权变更时令成功审计写入失败，核对接口报告失败、授权版本及原授权不变，查询不到该次成功审计。恢复写入后正常提交，确认新授权和相应成功审计同时可见。

[[AUD-06]]
==== AUD-06 保存可核对的审计信息

前置条件:: 审计事件包含约定的对象和目标，中心能够从认证及业务事实确定其来源和操作者。
功能描述:: 记录来源、事件时间、操作者、操作和对象、可用的结果及关联标识，并在“审计详情”提供经过处理的“变更前”与“变更后”。
业务规则:: 按事件保存可核对的最少操作者信息和角色快照。用户变名、停用、撤权或删除后仍能确认历史事件的归属。课程事件的对象类型须与对象标识匹配，可选的变更前后值使用白名单内的安全 JSON 对象。
异常处理:: 对象标识不合法、对象类型与标识不符、快照形态无效或含禁止的敏感字段时，拒绝课程审计写入。无查询资格时不得返回快照。
验收标准:: 撤销角色后可查看必要的变更信息，后续删除操作者仍保留审计记录和历史角色快照，页面能标识“已删除”。提交类型与标识不匹配或含敏感字段的事件时无新增记录。未经授权不能取得事件详情。

=== G. 管理界面

[[UI-01]]
==== UI-01 使用同一套管理前端

前置条件:: 两种后端可在测试环境运行，使用同一套接口契约和等价的业务数据。
功能描述:: 管理前端可配置连接结构化或 DDD 后端，提供同样的业务入口和操作流程。
业务规则:: 切换后端时使用同一份前端，业务输入、授权决定、界面反馈与最终状态均按同一契约处理。
异常处理:: 后端暂不可用时，界面显示可识别的故障。已提交结果按服务端状态核对。
验收标准:: 分别连接两套真实后端，经“登录”进入“用户管理”，完成角色指派，查看“有效权限”，再在“操作审计”确认变更。对照两次操作的可见结果和最终业务状态。

[[UI-02]]
==== UI-02 提供完整管理入口和基础工作台

前置条件:: 用户已登录中心，相应入口取决于当前 UI 权限及操作所需的 API 权限。
功能描述:: 提供“系统登记”“部门准入”“用户管理”“角色管理”“角色继承”“权限目录”“菜单与按钮”“API 操作”“UI ↔ API 映射”“鉴权解释”“操作审计”及“本人资料”等入口。
业务规则:: “首页”工作台入口要求首页 UI 权限，以及用户、角色和系统三项 API 查看权限。“可管理用户”按操作者的组织范围统计。无工作台资格时，默认进入“本人资料”。
异常处理:: 用不同状态区分无访问权限、页面不存在和服务暂不可用，并保留返回有权入口的途径。
验收标准:: 拥有首页 UI 权限及三项 API 查看权限的权限中心管理员能打开工作台。移除三项 API 查看权限之一后，账号不能访问工作台，仍可打开“本人资料”和其他获准页面。

[[UI-03]]
==== UI-03 展示直接权限和继承路径

前置条件:: 操作者有角色或受管用户的权限查询资格，已选目标系统。
功能描述:: 在角色及用户详情展示直接和有效授权，在“角色继承”中定位角色关系与来源路径。
业务规则:: 有效权限按种类及编码区分。菱形的多条继承路径可分别查看。展示停用节点及其对有效路径的影响，直接授权编辑只操作直接权限。
异常处理:: 对无效关系或成环请求显示服务端拒绝原因，并保留有效的继承图及可继续处理的选择。
验收标准:: 打开菱形关系的“有效权限”，同一权限显示一项、两个来源。停用其中一个中间角色后，另一条路径仍可查。反向添加会成环的关系时，页面显示拒绝，图中不出现该边。

[[UI-04]]
==== UI-04 完成用户和部门管理流程

前置条件:: 操作者拥有当前操作权限，并可管理所选用户及部门。
功能描述:: 在“用户管理”筛选分页、查看“基本资料”“角色指派”和“有效权限”，在“部门准入”查看和维护部门，按权限执行资料编辑、“变更状态”和“调动部门”等操作。
业务规则:: 指派候选来自用户当前部门与目标系统的合法准入选项。切换目标系统、变更部门或刷新数据后，按服务端当前结果更新选项。各类状态变更使用各自入口。
异常处理:: 选项尚未加载时不得提交。范围外、部门停用或无准入等情况按服务端反馈显示原因。提交失败后保持原业务状态。
验收标准:: 按姓名和部门筛选用户并翻页。选择“角色指派”，完成一次合法指派及撤销，再从“有效权限”核对结果。执行“调动部门”后应清空直接指派，目标部门的准入选项按新归属显示。

[[UI-05]]
==== UI-05 反馈关键操作和权限状态

前置条件:: 前端连接真实后端。测试包含有权账号、权限受限账号和至少一种可重试的接口故障。
功能描述:: 页面清楚反馈加载、空结果、校验错误、正常拒绝、会话失效和服务暂不可用，并支持在适用处“重试”。
业务规则:: 由当前授权决定是否进入管理页。保存授权后按新结果刷新权限及导航。桌面页的主要导航、表单和操作控件可用键盘到达。移动视口覆盖关键登录和管理流程。
异常处理:: 明确拒绝时显示“暂无访问权限”，无法核实权限时显示“权限刷新失败”。提交已成功而后续刷新失败时，提示刷新结果并保留查询实际状态的途径。
验收标准:: 在桌面完成登录、指派、撤销和菜单停用检查，并复核移动视口的关键流程。进入管理页时模拟权限刷新失败，点击“重试”后检查恢复。分别检验深链被拒、会话过期和“页面未找到”。

[[UI-06]]
==== UI-06 将工作台限制在基础管理范围

前置条件:: 操作者已取得 <<UI-02>> 所述工作台访问资格。
功能描述:: 显示基础的用户、角色、接入系统概况及有权访问的管理入口。
业务规则:: 统计按授权范围展示，本期功能范围包括基础管理计数。风险看板、热力图和独立业务统计大屏归入范围外。
异常处理:: 缺少访问资格时按 <<UI-02>> 进入本人资料或其他获准页。取数失败按 <<UI-05>> 反馈。
验收标准:: 有权用户能从“工作台”看到基础计数并进入获准页面。核对可见导航和对外 API 范围，均符合本期的管理与基础计数范围。

== 非功能需求

[[NFR-01]]
=== NFR-01 默认拒绝与明确错误

质量要求:: 身份无效、受众不匹配、受保护操作未登记、权限不足或无法取得可信授权结果时，受保护请求应停止处理。按契约区分输入错误、未认证、无权、资源不存在、业务冲突和服务不可用。已授权调用的鉴权查询可正常返回“不允许”的判定。
验收标准:: 分别发起未认证、已认证但无权、输入非法和调用不存在资源等请求，核对其可识别的结果。对“不允许”的合法查询，后续关联的业务请求仍须被拦截。

[[NFR-02]]
=== NFR-02 令牌验证及持续撤销

质量要求:: 课程接入的令牌符合契约，包含可验证签名、颁发者、单一受众、有效期和稳定主体标识。课程后端可取得公开验证密钥。轮换期间按契约校验仍在有效期内的旧凭证。授权以当前事实为准，退出、改密及账号停用导致的失效须跨服务实例及重启持续有效。
验收标准:: 检查过期、签名无效或受众不匹配的凭证均被拒绝。按契约轮换密钥并校验应仍有效的令牌。完成“退出”后重启测试实例，撤销的凭证仍不能访问。

[[NFR-03]]
=== NFR-03 授权变更及时生效及分页可用

质量要求:: 授权变更提交后的下一次访问按更新后的用户、系统和操作状态及有效权限判定。无法确认最新状态时拒绝许可。非权威缓存故障时，可按可信状态继续判断。对用户和审计等可增长数据先按查询及授权范围过滤，再返回当前页和匹配总数，固定条件下分页顺序稳定。
验收标准:: 在两个实例先验证许可，再撤权，下一次访问两实例均拒绝。读取期间若授权事实变化，取得新结论或明确报告不可用。权威状态暂不可读时不放行。在一万条合成用户数据中按部门和关键字分页，核对记录、总数和分页边界。

[[NFR-04]]
=== NFR-04 并发与变更完整性

质量要求:: 中心的部门调动、准入替换、角色指派、继承关系和本地审计各按业务规则完整生效。跨系统审计按 <<EXT-07>> 处理。并发处理应维持唯一部门、角色指派资格、继承无环及最后一位有效权限中心超级管理员保护。版本冲突按操作契约处理，失败时有关联的修改一并撤销。
验收标准:: 对同一用户并发调动或调整指派，完成后其部门、角色指派和授权一致。并发建立相反继承关系时，只保留成功请求对应的边。敏感业务变更因审计失败时无部分提交。

[[NFR-05]]
=== NFR-05 保护服务间信任边界

质量要求:: 服务端依据实际验证的身份和登记的操作作授权决定。用户和服务身份须同时通过验证，才能调用私有身份接口和课程审计。来自客户端的身份、系统、操作标识及转发信息不能改写可信事实。服务凭据只交由受信运行环境。
验收标准:: 使用提供额外身份或转发信息的请求时，决策仍由实际合法身份及登记操作决定。只提供用户凭证或只提供服务凭据的私有调用均被拒绝。

[[NFR-06]]
=== NFR-06 最小信息披露

质量要求:: 页面、接口、技术日志和审计快照按需要提供字段。业务响应只提供当前调用所需的信息，登录凭证仅由约定的签发接口返回。密码、密码摘要、令牌、私钥、服务凭据和不必要的个人信息不得出现在日志或审计快照中。联系方式按角色和业务需要返回或脱敏，审计前后值使用约定的允许字段。
验收标准:: 分别以本人、管理者和课程目录调用方查看资料，核对字段范围。提交包含测试用敏感字段的异常请求，检查响应、日志和审计快照不返回敏感值、配置或内部堆栈。

[[NFR-07]]
=== NFR-07 可配置、安全地部署

质量要求:: 服务地址、证书及凭据由受控配置供应。部署使用 HTTPS 和隔离的服务间访问。在同一合格数据基线中切换后端，前端、现有账号、组织、角色和审计应继续可用。首次部署使用受控初始化凭据。
验收标准:: 在授权环境切换两种后端并保留数据，完成核心管理操作及真实课程请求。检查公开入口不能访问私有身份接口，初始化凭据不进入源码、镜像或客户端。
