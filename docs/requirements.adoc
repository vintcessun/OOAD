== 固定范围与安全不变量

* 单组织、用户唯一所属部门；没有公司模型。部门用于组织管理子树与直接角色准入，不提供业务数据范围。
* 角色归属系统，senior→junior同系统DAG支持多父、传递、菱形去重与来源路径；停用节点切断。写事务持授权锁防并发成环。
* 跨部门调动清空该用户的全部直接角色指派，在新部门重新指派时校验准入。提交原部门保留指派。共享角色权限与其他用户的指派保持原状。授权上界包括目标系统有效权限及受保护的角色码。
* 创建、改名和维护准入使用部门编辑权限。启停和删除拥有独立权限。停用的非根叶部门保留成员和既有指派，停止接收新成员、子部门和指派，并从课程目录隐藏。
* UI菜单/按钮与API权限分种类；API目录独立登记、UI↔API显式映射只追踪、不赋权；未知操作默认拒绝。
* JWT无角色权限claim、稳定sub/单aud，状态/撤销先于超级管理员旁路；MySQL为授权版本与jti撤销事实源，缓存故障不得用旧许可放行。
* 权限中心保存统一身份和集中审计，不保存课程业务副本；教师Service保留对象授权，copyCourse全局teacher不等于非组长拥有CC。
* 外部审计与私有服务接口双重验证用户Bearer及可信服务密钥；公开代理拒绝私有根前缀，浏览器不获得服务密钥或完整API能力清单。
* 不实现RBAC2/3、多租户、业务scope/selfOnly、临时授权、风险看板、热力图/统计大屏；dashboard仅基础计数。

== 六组范式对照与新旧测试映射

S01继承验环、S02准入指派/调动、S03闭包、S04课程准入、S05审计幂等、S06业务/成功审计同事务必须外部等价、内部职责不同。
结构化规则在Service过程，DDD规则在Role/User/RoleHierarchy/领域策略，应用编排端口及事务；不得共享算法让对比失真。

一期多公司/scope/selfOnly断言不能原样套入RBAC1，也不能顺手删除仍适用的安全预期：

[cols="2,3"]
|===
|历史断言 |RBAC1保留/替换
|公司隔离、scope部门覆盖 |替换为系统/aud隔离、组织管理子树、部门直接准入；继续拒绝跨边界读取/写入。
|旧资源×动作、菜单、selfOnly |替换为UI/API独立、BUTTON、真实ApiOperation及显式映射；保留默认拒绝和服务端授权。
|旧角色并集/撤权 |扩展同系统DAG、多来源、停用切断、两级缓存和多JVM即时失效。
|旧认证/越权/账号保护 |继续保留凭据失败、状态/tokenVersion/持久注销、授权上界及最后管理员，不以重构为由移除。
|旧独立事务成功审计 |升级为业务/SUCCESS同事务；拒绝仍独立，新增requestId幂等/跨主体异体拒绝和故障回滚。
|===

历史M0/M1/M2用于记录基线、删除旧演示和启动布局；不能作为当前RBAC1完成证明。
