== 测试与覆盖率配置

JUnit 测试负责构造输入、执行代码并断言业务结果；JaCoCo 记录这些测试执行到的 Java 代码，生成覆盖率报告并检查门槛。
业务结果由测试断言检查；覆盖率用于找出尚未执行的代码和分支。

配置依据：link:{project-root}/pom.xml[pom.xml（父 POM）] 和 link:{project-root}/rbac-structured/pom.xml[pom.xml（rbac-structured POM）]。
父 POM 在 pluginManagement 中管理 JaCoCo 0.8.12，业务模块显式声明插件后继承并启用它。
报告按启用插件的模块生成，当前没有聚合报告模块。

[cols="1,2,3",options="header"]
|===
|阶段 |插件目标 |实际含义
|initialize |prepare-agent |设置测试 JVM 使用的 Java agent 参数。
|test |report |测试执行后，根据执行数据生成报告；这是本项目显式绑定的阶段。
|verify |check |检查当前配置的覆盖率门槛，不达标使构建失败。
|===

因此 `test` 可以生成报告，但验收应执行 `verify`。
直接调用 `jacoco:report` 不会自动执行测试；`-DskipTests` 和 `-Dmaven.test.skip=true` 不能用于完整验收。

== 测试环境

需要 JDK 21、可用的 Maven Wrapper、MySQL 8.0 和 Redis 7。
仓库 Wrapper 固定 Maven 3.9.9，首次运行可能下载 Maven 与依赖；Docker 是创建独立测试服务的方便方式。

WARNING: `IntegrationTestBase` 首次执行 Flyway clean/migrate，后续测试截断并恢复表，还会执行 Redis FLUSHDB。只能连接可丢弃的专用测试库与专用 Redis 实例。不能指向开发业务库、演示数据或生产服务。

当前测试配置见 link:{project-root}/rbac-structured/src/test/resources/application-test.yml[application-test.yml]：

[cols="2,3",options="header"]
|===
|环境变量 |用途
|TEST_DB_URL |测试 JDBC URL；默认连接 localhost:13306/rbac_test。
|TEST_DB_USER、TEST_DB_PASSWORD |测试数据库凭据。使用本次独立测试实例的值，不复制生产凭据。
|TEST_REDIS_HOST、TEST_REDIS_PORT |测试 Redis 地址；默认 localhost:16379。
|===

测试使用真实数据库与缓存，需要先启动相应服务。
不要用 Maven `-T`、JUnit 并行配置或多个测试进程同时操作同一套测试数据，否则重置过程会互相干扰。
下面使用不同于默认值的 23306 / 26379 端口，显式指定连接，避免误用已有服务。

== Windows PowerShell 完整操作

=== 检查工具

[source,powershell]
----
java -version
.\mvnw.cmd -version
docker version
----

应看到 Java 21 和可连接的 Docker Server。若 JAVA_HOME 与 java 命令不一致，以 Maven 输出的 Java 版本为准。

=== 创建独立测试服务

容器名已存在或端口占用时，应先确认归属，或自行选取新名称和端口并同步修改连接参数；不要直接删除其他人的容器。
以下凭据在运行时随机生成，仅保存在当前 PowerShell 进程环境中，不写入源码或命令文本。

[source,powershell]
----
$env:TEST_DB_USER = 'root'
$env:TEST_DB_PASSWORD = [guid]::NewGuid().ToString('N')
$env:MYSQL_ROOT_PASSWORD = $env:TEST_DB_PASSWORD
$env:MYSQL_PWD = $env:TEST_DB_PASSWORD
$env:TEST_DB_URL = 'jdbc:mysql://127.0.0.1:23306/rbac_test?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false'
$env:TEST_REDIS_HOST = '127.0.0.1'
$env:TEST_REDIS_PORT = '26379'

docker run -d --name ooad-jacoco-mysql -p 127.0.0.1:23306:3306 --env MYSQL_ROOT_PASSWORD --env MYSQL_DATABASE=rbac_test mysql:8.0 --character-set-server=utf8mb4
docker run -d --name ooad-jacoco-redis -p 127.0.0.1:26379:6379 redis:7-alpine
----

容器创建成功不等于数据库初始化完成。稍后执行下列检查，MySQL 返回 `1`、Redis 返回 `PONG` 后再继续；初始化期间可间隔几秒重试。

[source,powershell]
----
docker exec --env MYSQL_PWD ooad-jacoco-mysql mysql -uroot -Nse 'SELECT 1'
docker exec ooad-jacoco-redis redis-cli ping
----

保持在同一个终端运行，避免丢失刚设置的环境变量。不要输出环境变量值或提交带凭据的运行日志。

=== 执行完整测试和门槛检查

[source,powershell]
----
.\mvnw.cmd -B clean verify
if ($LASTEXITCODE -ne 0) { throw '测试或覆盖率检查失败，请查看 Maven 输出。' }
Start-Process '.\rbac-structured\target\site\jacoco\index.html'
----

`clean` 清除上次构建与覆盖率文件，使本次报告不混入旧执行数据。
若 Maven Central 连接不稳定，可以使用仓库提供的镜像配置，其他参数不变：

[source,powershell]
----
.\mvnw.cmd -B -s deploy/maven-settings-huawei.xml clean verify
----

镜像选项影响 Maven 依赖解析；Wrapper 自身的下载地址由 `.mvn/wrapper/maven-wrapper.properties` 单独指定。

== Linux / macOS 操作

同样使用专用容器。数据库口令由交互式输入提供，终端不回显；不要填写生产口令。

[source,bash]
----
java -version
./mvnw -version
docker version

read -r -s -p '输入本次临时测试库口令: ' TEST_DB_PASSWORD
printf '\n'
export TEST_DB_PASSWORD
export TEST_DB_USER=root
export MYSQL_ROOT_PASSWORD="$TEST_DB_PASSWORD"
export MYSQL_PWD="$TEST_DB_PASSWORD"
export TEST_DB_URL='jdbc:mysql://127.0.0.1:23306/rbac_test?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false'
export TEST_REDIS_HOST=127.0.0.1
export TEST_REDIS_PORT=26379

docker run -d --name ooad-jacoco-mysql -p 127.0.0.1:23306:3306 --env MYSQL_ROOT_PASSWORD --env MYSQL_DATABASE=rbac_test mysql:8.0 --character-set-server=utf8mb4
docker run -d --name ooad-jacoco-redis -p 127.0.0.1:26379:6379 redis:7-alpine

# 初始化完成后，以下检查应分别返回 1 和 PONG；未就绪时稍后重试。
docker exec --env MYSQL_PWD ooad-jacoco-mysql mysql -uroot -Nse 'SELECT 1'
docker exec ooad-jacoco-redis redis-cli ping

# 确认服务就绪后执行；终端应以 BUILD SUCCESS 结束。
./mvnw -B clean verify
----

浏览器打开 `rbac-structured/target/site/jacoco/index.html`。
镜像命令为 `./mvnw -B -s deploy/maven-settings-huawei.xml clean verify`。

== 运行指定测试

仅验证权限中心及其上游依赖：

[source,powershell]
----
.\mvnw.cmd -B -pl rbac-structured -am clean verify
----

`-pl` 选中模块，`-am` 同时构建所需模块，避免单独编译时找不到 rbac-contract。
Linux/macOS 将 `.\mvnw.cmd` 换为 `./mvnw`。

没有测试数据库时，可以先执行无需真实服务的架构、契约和 Redis 故障模拟测试：

[source,powershell]
----
.\mvnw.cmd -B -pl rbac-structured -am clean test '-Dtest=ArchitectureTest,ContractRoutesTest,RedisFailureTest' '-Dsurefire.failIfNoSpecifiedTests=false'
----

最后一个参数让没有这些测试类的上游模块不因“未找到指定测试”失败。
这个命令产生所选测试的局部覆盖率；完整验收执行 `clean verify`。
运行局部测试后需要重新 `clean verify` 才能提交完整报告。

当前集成测试类也以 `Test` 结尾，由 Surefire 在 test 阶段运行；没有单独配置 Failsafe 的集成测试阶段。
集成测试随 `test` 阶段一同执行。

== 报告位置与阅读方法

[cols="2,3",options="header"]
|===
|路径 |用途
|rbac-structured/target/site/jacoco/index.html |人工查看包、类、方法和源代码覆盖率。
|rbac-structured/target/site/jacoco/jacoco.xml |机器读取的覆盖率计数。
|rbac-structured/target/site/jacoco/jacoco.csv |表格分析。
|rbac-structured/target/jacoco.exec |agent 执行数据，不是可直接阅读的报告。
|rbac-structured/target/surefire-reports/ |测试数量、失败断言、错误与跳过记录。
|===

打开 HTML 后先看 Total，再进入 `com.xmu.rbac.structured.service`，最后检查具体类与源代码行。
红色表示未执行，绿色表示已覆盖，黄色提示部分覆盖；分支标记应结合条件两侧的测试输入理解。
报告分别统计指令覆盖率和行覆盖率。若首页只展示 Missed Lines 与 Lines，可计算 `(总行数 - 未覆盖行数) / 总行数`，或读取 XML 的 LINE 计数。
分支覆盖率同样按已覆盖分支占总分支的比例计算。

当前门槛：

[cols="2,1,3",options="header"]
|===
|范围与指标 |最低比例 |配置口径
|BUNDLE 的 LINE |70% |rbac-structured 中未被排除的生产类。
|BUNDLE 的 BRANCH |60% |同上。
|匹配 `*.service` 的 PACKAGE 的 LINE |85% |当前 service 包；新增子包时检查包名是否匹配该表达式。
|===

排除项为 `**/dto/**`、`**/entity/**`、`**/config/**`、`**/*Application.class`。
上述指标统计启用 JaCoCo 的后端模块；模拟业务模块和前端使用各自的测试报告。

== 本项目需要关注的测试场景

[cols="2,3",options="header"]
|===
|测试类 |关注点
|ArchitectureTest |三层依赖、实体数据职责、Service 无状态、不用继承组织 Service。
|ContractRoutesTest |契约声明与接口权限对应。
|RedisFailureTest |缓存故障回源、注销校验故障的保守处理。
|AcceptanceTest |登录、越权、范围不可拼接、跨公司指派、回收后失效、权限解释、多副本一致性。
|ManagementApiTest |用户与角色管理、批量管理、保护规则、菜单、统计与错误路径。
|ExcelImportIntegrationTest |Excel 导入与重复导入同步。
|===

补测试时先对应需求或风险构造断言，例如“审批只在 A，查看只在 B”必须拒绝 B 的审批；不能只为让某一行变绿而调用方法。

== 常见失败排查

[cols="2,3",options="header"]
|===
|现象 |处理方向
|Java release 21 不支持 |检查 Maven 使用的 JDK，而不仅是编辑器中的项目 SDK。
|MySQL 连接失败、拒绝访问 |确认实例就绪、端口、测试 URL 和凭据来自同一临时实例；不要把密码粘到报错截图。
|Redis 连接失败 |确认专用实例和 TEST_REDIS_HOST/PORT；不要改用业务 Redis 凑合测试。
|依赖下载失败 |确认网络及 Maven 镜像配置，不以跳过测试代替解决依赖问题。
|没有 jacoco.exec 或报告提示缺少执行数据 |确认执行了测试且启用了插件；检查是否跳过测试、覆盖 argLine 或将 forkCount 设为 0。
|测试通过但 verify 失败 |查看 JaCoCo 指出的包和指标，补充有断言的缺失场景；不要随意降低门槛。
|HTML 仍显示旧结果 |先确认文件更新时间，再完整 clean verify；不要将历史报告当作本次结果。
|局部测试报告很低 |这是局部执行的正常边界；完整结果需全部测试重新运行。
|测试失败且 report 未执行 |先看 surefire-reports 修复失败，重新运行；构建结果以完整 verify 的执行状态为准。
|===

agent 需要保留测试 JVM 的 argLine；如果以后自定义 Surefire 的 JVM 参数，应按官方说明保留 JaCoCo 注入的值。
当前不需要为使用 JaCoCo 再添加第二份插件配置。

== CI 与提交材料

link:{project-root}/.github/workflows/ci.yml[ci.yml（CI 工作流）] 创建 MySQL、Redis 服务，执行 `./mvnw -B verify`，并尝试上传 `jacoco-report`。
下载某次运行的 artifact 前，应先检查该次 verify 是否成功；失败运行也可能上传部分产物。
CI 的干净检出环境与本地 clean 的目的相近，提交材料使用对应代码版本且 verify 成功的报告。

课程提交建议包含：

. 本说明、代码提交号或明确的工作区版本、执行时间、JDK/Maven 版本与实际命令。
. 完整 `target/site/jacoco/` 目录，包括 index.html、样式文件和类详情页面。
. Surefire 测试统计、JaCoCo 总体与 service 包指标，以及 verify 成功或失败结论。
. 未执行的范围和失败原因；输出资料中去除任何凭据及人员信息。

完整运行后，根据本次输出填写记录表：

[cols="1,2",options="header"]
|===
|项目 |本次记录
|执行日期、版本、命令 |由实际执行者填写
|测试数 / 失败 / 错误 / 跳过 |取本次 Surefire 报告
|整体行 / 分支覆盖率 |取本次 JaCoCo 报告
|service 行覆盖率 |取本次 JaCoCo 报告
|verify 结论与未执行范围 |如实记录
|===

测试结束后，仅在确认由上述命令创建且无需保留数据时删除两个专用容器：

[source,shell]
----
docker rm -f -v ooad-jacoco-mysql ooad-jacoco-redis
----

关闭临时终端可清理进程环境。不要使用 docker system prune 等与本次测试无关的全局清理命令。
