= 独立共享 HTTP 黑盒验收
:toc:

== 权威与范围

`tools/acceptance/` 只通过真实 HTTP 调用两个独立可执行 jar；不导入 Java Service、领域算法或 Spring 测试源码。
精确输入输出优先 `implementation-contract.adoc`、`schema-contract.adoc`；完整需求来源 `sources/requirements-final.md`（含 §15/18/20/24）。
本测试不兼容一期 company/scope/selfOnly 接口，也不以旧 jar 的行为修改冻结合同。
共享的是测试，不共享后端核心实现。没有业务代码变更，也不执行 Git 提交。

本套证明权限中心的 HTTP/数据库行为；不能代替真实课程 Service 对象级权限、网关上游路由、浏览器 UI、Swarm、JaCoCo 或 UML 核验。
旧版认证、越权、事务、缓存安全要求保留并映射到下表，不因重构删除。

== 安全运行

先在父工程构建两个真实可执行 jar；并行实现期间不要重建或运行其他代理正在使用的服务。
以下构建命令应由主代理在两个实现完成后执行（不是本次已执行证据）：

[source,powershell]
----
$env:JAVA_HOME = 'C:\path\to\jdk-21'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
.\mvnw.cmd -pl rbac-structured,rbac-ddd -am package -DskipTests
cd tools/acceptance
npm ci --ignore-scripts --no-audit --no-fund
npm test
# 使用本机专用 MySQL 的凭据；不要使用生产连接串。
$env:ACCEPTANCE_DB_USER = 'root'
$env:ACCEPTANCE_DB_PASSWORD = '<本机专用实例的环境凭据>'
npm run acceptance -- --module=both
----

也可分别执行 `node run.mjs --module=structured` 或 `--module=ddd`。
`--report=C:\Temp\rbac-contract-report` 指定报告目录；缺省报告、JVM 日志、临时密钥目录均位于系统临时目录、仓库之外。
终端仅输出模块/场景/pass/fail 和报告位置，不输出 HTTP 请求、响应、JWT、密码或服务密钥。
报告中的响应摘要为去随机字段后的 SHA256，不持久化原始敏感响应。

* JDK 严格检查 JAVA_HOME/release 为 21，不使用 PATH 上的 Java8；Node >=22。
* 固定数据库连接只允许 literal `127.0.0.1:13306`。主机/端口覆盖参数仅用于验证防护；localhost、IPv6、远端和 3306 均拒绝。
* 新库为 `rbac1_contract_<structured|ddd>_<13位timestamp>_<8位hex>`；仅 CREATE 成功后登记所有权，DROP 前再次验证目标，仅删本次创建的库。
* MySQL 权限需要 CREATE/DROP DATABASE、表读写及 TRIGGER。触发器只建在自有新库；故障场景 finally 删除，不暂停共享 MySQL。
* Redis 仅访问专用 `127.0.0.1:16379`，先 PING；namespace 等于新库名加冒号。结束用 SCAN MATCH 自有前缀，再逐项检查前缀后 DEL，不执行全实例清理/重启。
* structured 两实例端口 19081/19181，DDD 19082/19182。预检端口若被占用立即环境失败，绝不杀已有进程。只终止自身 spawn 并持有 ChildProcess 对象的 JVM。
* 每模块两实例共享同一新库、临时 RSA PKCS8/SPKI、issuer、kid、namespace；L1 为两个独立 JVM。模块之间数据库、namespace、密钥分离。
* 注入 DB_URL/USER/PASSWORD、REDIS_HOST/PORT、RBAC_CACHE_NAMESPACE、RBAC_JWT_PRIVATE_KEY_FILE/PUBLIC_KEY_FILE、RBAC_JWT_KID/ISSUER、RBAC_BOOTSTRAP_PASSWORD、RBAC_AUDIT_SERVICE_KEY、SPRING_PROFILES_ACTIVE=test。
* 每个新账号/root 都先登录、调用 POST /api/v1/auth/password、断言旧 token 失效，再重新登录。密码、用户、课程对象均为虚构 fixture。
* cleanup 停自有进程、清自有 Redis namespace、删自有新库、移除私钥/公钥；日志保留仓库外以便诊断。SIGINT/TERM 请求在受控清理后退出，强制关闭宿主 Node/机器断电不能保证 finally；出现残留时只能依据报告中的完整所有权名称人工确认清理。

== 判定、报告与限制

`report.json` 为表格化 `rows[]`：module、scenario、status、classification（失败时）、durationMs、HTTP observations、规范化 result。
总表包含 command、exitCode、summary、模块新库名/端口/仓库外日志目录。
每次实现运行独立建立类型化引用别名；保留 user/department/role 等关联、subject、version、继承路径内部顺序和分页 items 顺序，只有明确集合字段排序。
随机 requestId 按请求发起顺序建立别名；仅生成的 trace/审计时间等元数据去噪，未知引用保留而不静默删除。
反例测试保证错误部门、错误subject、错误继承路径和颠倒分页顺序不能被归一化掩盖。
JWT/JWKS不比较随机密钥内容，而分别做密码学和字段断言。
不把两个相同的错误实现当一致通过：对比前要求双方每个场景都 pass。
唯一并发例外是ROLE-03中未指派、空权限的RACE_A/RACE_B对称反向写：调度器可任选获胜方向。
原始HTTP方向与结果完整保存，每边必须恰好一200/OK和一409/ROLE_CYCLE，SQL还必须证明唯一持久边恰是获胜请求的方向；
T21仅对此固定隔离角色对比较合法结果集，拒绝其它角色、重复方向、双成功。其它关系、顺序、版本一概不宽免。
对应反例测试证明该规则不会抹掉普通DAG路径或分页顺序差异。

[cols="1,3"]
|===
|退出码 |含义
|0 |选定模块场景及双实现比较全部通过
|1 |真实 HTTP/DB 合同断言失败或场景执行错误；新接口404必须 FAIL，不 skip
|2 |JDK/端口/依赖实例/建库权限/JVM readiness/清理等环境阻断，或中断；不宣称业务 RED
|===

若 SETUP 新端点缺失，SETUP 真实失败，依赖该状态的后续场景仍登记 fail（不跳过、不伪造独立成功）。
首次部署启动失败可能是过时 M2 jar、配置、迁移或应用启动错误，需看仓库外日志；仅凭 readiness 失败不能断言业务失败。
数据库分页通过可观测输出与数据库 LIMIT/OFFSET 校验；是否内部使用 JPA 真正数据库分页还需实现代理的 SQL/源码/性能证据，本黑盒不冒称能观察内部加载方式。
不关闭共享 Redis/MySQL，因此不能将本套误称为完成整个实例宕机测试；本地同步审计故障通过仅自有 schema 的 trigger 注入。

== 工具护栏与候选至最终的真实执行

独立 package-lock 已生成；最新 `npm test`：21项通过、0失败、0跳过，包含类型化引用反例、两个真实本地 stub 的302/307/308不外发、环境污染隔离和数据库护栏。
