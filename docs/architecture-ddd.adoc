= RBAC1 DDD架构：独立领域实现与证据边界
:toc:

== 当前事实

rbac-ddd已包含真实domain、application、interfaces及infrastructure业务类型，*不再是只有health/info的M2启动骨架*。
它独立使用JPA/MySQL、Redis、Flyway、JWT与缓存适配，仅共享rbac-contract的纯HTTP协议类型/错误词汇、开发DDL及外部黑盒夹具，不依赖rbac-structured业务。
本文按现行生产源码说明；部分旧package-info/类名仍带Skeleton，不应据此否认现有业务，也不能据源码存在宣称最终验收完成。

RbacDddApplication扫描自身包；默认8082，部署SERVER_PORT可统一为`${RBAC_PORT:-8081}`；没有全局context-path。
ImplementationHealthIndicator已替代旧骨架探针，元数据为backend=ddd、stage=M5-RBAC1-verified、businessReady=true；整体仍由真实依赖探针汇总，不能把实现标识当外部部署背书。
当前112项DDD测试与25场景真HTTP及T21已通过；源码存在不是证明，结果与hash见最终验收报告。旧“业务404/无需数据库/只21骨架测试”均不是现行事实。
依据为link:implementation-contract.adoc[实施合同]、link:schema-contract.adoc[15表合同]、link:course-integration-contract.adoc[课程私有投影合同]。

== 依赖方向与真实职责

[source,text]
----
interfaces.rest → application → domain / domain.port
infrastructure → domain.port（端口实现）/ domain（恢复模型）
Spring启动装配全部技术组件；domain不反向依赖外层或框架
----

[cols="1,3"]
|层 |现行类型及职责
|interfaces.rest |IdentityController、DirectoryController、RoleController、ResourceController、AuthorizationController与IntegrationIdentityController映射HTTP；RestSupport/DirectoryViews/ResourceViews及dto白名单组装VO；ApiExceptionAdvice输出裸错误；RegisteredApiInterceptor使用服务端路由与认证上下文，不计算角色闭包。
|application |IdentityApplicationService、DirectoryApplicationService、RoleApplicationService、ResourceApplicationService、AuthorizationApplicationService、AuditApplicationService、IntegrationIdentityApplicationService编排用例；事务内锁/加载、调用领域规则、保存、版本递增及审计。GrantIntegrityService加载变更后事实供最后管理员策略判断。
|domain |Role、User为有行为模型；RoleHierarchy为DAG值图；DepartmentEligibility、AuthorizationPolicy、OrganizationPolicy、ResourcePolicy、LastAdministratorPolicy承载规则；AuditFact表达不可变审计事实及幂等重放约束；ApiOperation、Permission区分全局策略与权限种类。
|domain.port |AuthorizationRepository、DirectoryRepository、ResourceRepository、AuditRepository、EffectiveCache、OperationContract、CredentialEncoder、TokenProvider定义能力边界；不继承JpaRepository，不引入JPA/Redis/HTTP对象。
|infrastructure |JpaAuthorizationRepositoryAdapter、JpaDirectoryRepositoryAdapter、JpaResourceRepositoryAdapter、JpaAuditRepositoryAdapter实现仓储；独立entity与repository为持久化模型。VersionedEffectiveCache实现L1/L2；RsaTokenProvider/BcryptCredentialEncoder负责密码学；BootstrapInitializer做占位口令引导；OpenApiOperationContract/RouteContractVerifier读取及核验合同；LayerLoggingAspect记录技术元数据。
|===

领域对象与持久化实体分离：RoleEntity不是Role聚合；适配器恢复领域状态和保存变化，不把JPA实体直接传入Controller。
应用可以依赖Spring事务与JSON编排，但不能依赖infrastructure实体或JpaRepository；domain只依赖JDK/自身端口，不能依赖Spring/JPA/Jackson或application/interfaces。
BackendIsolationTest、DomainArchitectureTest包括生产类扫描及故意违规反例；这些规则不能靠空包通过冒充DDD实现，也不代替业务验收。

== 六组实际协作

[cols="1,3"]
|场景 |真实职责分配与必须保留的安全期望
|S01 继承加边 |RoleApplicationService先lockGrants，加载RoleHierarchy；RoleHierarchy.link拒绝自环、跨系统、重复及反向可达；应用保存边、检查上界/最后管理员、递增版本并同事务审计。数据库锁负责并发串行化，必须实际测反向并发。
|S02 准入与调动 |User.assign 调用 DepartmentEligibility.requireEligible。跨部门调动时，User.transfer 清空本人的角色指派。DirectoryApplicationService 核对原、新部门的管理范围并在同一事务中保存。
|S03 有效权限 |RoleHierarchy.paths保留有效路径、停用节点切断；AuthorizationPolicy.calculate计算直接/有效角色、去重权限和多条来源，identityRole投影受控。应用加载事实/版本并协调缓存，不从UI映射推导API。
|S04 课程准入 |ApiOperation/AuthorizationPolicy判定系统级permission/requiredRole；可信课程网关另由固定method/path解析operationId；私有authorities投影真实API能力/ROLE_身份。teacher准入不能伪造CC，教师Service保留对象规则。
|S05 幂等审计 |AuditFact.requireReplay绑定来源系统、主体和payload_hash；AuditApplicationService规范化安全JSON并使用独立插入事务，唯一冲突回滚后重读，提交后201；外部查询按aud隔离。
|S06 敏感业务 |应用事务在同一MySQL提交业务、全局版本与SUCCESS审计；LastAdministratorPolicy保护可用性不变量。拒绝事实独立事务，不以AOP技术日志代替审计。
|===

上述为已存在的职责，不是六组验收已全部通过。尤其并发、完整新闭包授权上界、最后管理员间接破坏、故障回滚、跨aud和规范化幂等仍必须用真实数据库及黑盒证明。

== 路由、缓存与安全配置

OpenApiOperationContract 读取中心 68 项 OAS，RouteContractVerifier 核对实际 Controller 及持久注册。管理入口保护固定路由的 API 元数据。
HttpSecurityConfiguration关闭会话、表单和Basic；Bearer与细粒度授权由接入层/应用统一验证，不能将框架permitAll理解成匿名业务开放。
根/auth七操作与两个私有投影已有Controller；私有端点即使公开代理阻断仍需有效Bearer和服务密钥，身份查询还需TEC与admin，不能接收客户端subject/system指定目标权限上下文。

AuthorizationApplicationService每次读取MySQL授权版本，写事务内不消费/回填缓存；VersionedEffectiveCache以namespace:authz:system:user:version为键。
当前DDD适配为Caffeine L1约30秒、Redis L2约60秒，TTL只清理旧键；Redis异常回源，权威数据库失败不能以旧缓存放行。与结构化缓存实现/TTL不同不改变即时撤权合同，跨JVM与延迟回填仍须验收。
MySQL持久化jti撤销，改密更新tokenVersion；RsaTokenProvider签发RS256单aud身份JWT，生产配置共享私钥/公钥、issuer/kid及轮换旧公钥，临时密钥只在明确dev/test配置下允许。

LayerLoggingAspect覆盖interfaces/application及持久化/身份/缓存适配，记录traceId/layer/class/method/duration/result/exceptionType；不记录参数、返回对象、异常消息、token或服务密钥。日志不等于审计事务。

== CloneFactory边界

两后端使用根 POM 固定的 CloneFactory 0.0.2。DDD 的角色创建 record 映射到命令；角色与 UI 的结果、响应及持久化快照通过生成器读写 record。适配器负责系统和权限关联，聚合构造器维护领域不变量。
工具按getX/setX浅拷贝，不自动复制record accessor、boolean isX或转换类型。受控Bean采用包装类型及字段白名单；不复制密码、actor、系统归属或实体内部状态到外部VO。
聚合构造与业务行为仍由领域负责；字段复制不等于领域规则，也不能把结构化实体借来伪装DDD模型。
CloneBoundaryTest与架构测试需随实际构建验证，不能仅因处理器在POM就声称安全映射验收完成。

== 双后端最终门槛

两后端分别构建/启动、各用隔离库与缓存命名空间，复用同一逻辑黑盒请求/预期，不复用授权算法。
共享HTTP验收需比较状态码、稳定错误码、规范化成功体、审计与最终数据库事实；同一前端切换验证真实登录、组织/角色DAG/UI/API管理及桌面/手机路径，不再测“登录404”作为成功。
同源代理、健康UP、M2截图、单个领域单测或历史覆盖率都不能替代这一门槛。
当前本地实际验证见link:final-acceptance.adoc[最终验收]与link:test-plan.adoc[测试计划]；DDD行91.01%/分支71.40%，application约86.82%并执行原85%业务层门槛。外部部署与未执行容量/灾备不据此推定。另一实现见link:architecture-structured.adoc[结构化架构]。
