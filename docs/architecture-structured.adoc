== 现行边界

rbac-structured已按RBAC1收缩，非一期RBAC0；rbac-ddd也已有独立领域与业务实现，不再只是M2骨架。
两后端只共享rbac-contract的OAS、纯HTTP类型/错误词汇、DDL/种子和外部黑盒夹具，不共享核心授权Service/算法。
本页说明实际源码职责；49项结构化JUnit、25场景真HTTP及T21、事务故障/并发、课程12例和覆盖率均已有真实结果，完整证据见最终验收，不从架构图推导运行成功。
权威依据为link:implementation-contract.adoc[实施合同]、link:schema-contract.adoc[数据库合同]及link:course-integration-contract.adoc[课程集成合同]。

== 实际分层

[source,text]
----
HTTP → Controller / PermissionInterceptor → Service → Mapper / Store → MySQL
                                           授权过程 → L1 / Redis L2
entity：表记录；dto：输入/身份/输出边界；config：装配、trace与AOP
----

[cols="1,3"]
|===
|层及实际类型 |职责
|controller |AuthController提供教师七操作/JWKS；ManagementController提供/api/v1管理；IntegrationIdentityController提供两个私有服务接口。PermissionInterceptor取服务端匹配路由、验证Bearer并控制中心管理入口；GlobalExceptionHandler输出裸字符串错误码。
|身份Service |AuthenticationService处理登录、持久注销、改密及本人投影；TokenService负责RS256/JWKS/共享密钥和声明校验；BootstrapService只引导UNINITIALIZED口令并核验中心注册数据。
|授权Service |AuthorizationService以过程计算同系统DAG闭包、去重和来源路径；角色码匹配、中心入口、组织子树、根部门、授权上界及最后管理员保护均在服务过程内实现。
|管理Service |ManagementService处理系统/部门/用户/角色、准入、指派、加删继承及权限；ResourceService处理MENU/BUTTON树、API目录、显式映射与判定解释。移部门与状态是独立操作。
|审计/集成Service |AuditService负责可信服务密钥、安全JSON、同步幂等、查询隔离及审计投影；IntegrationIdentityService只投影当前aud的真实API能力/ROLE_身份，身份查询还要求TEC和admin。
|mapper |Store封装EntityManager查询/稳定数据库分页；UserMapper、GrantVersionMapper提供排他锁，其他Mapper为Spring Data JPA接口。此处Mapper不是MyBatis，不承载业务规则。
|entity / dto / config |15表对应数据实体只持外键id和字段；Inputs等DTO禁止未知字段；Views白名单输出。WebConfig装配严格JSON类型/BCrypt与路由校验；TraceFilter生成服务端trace；LayerLoggingAspect记录技术元数据。
|===

结构化规则在Service而不是实体行为中表达；Service字段为final依赖/缓存等，不用继承组织业务过程。
ArchitectureTest约束Controller不能绕过Service访问Mapper、Service不依赖Controller/config、Mapper不反向依赖Service、实体只含数据及禁用MyBatis。本轮已真实执行；不能以规则存在代替其测试结果。
CloneFactory 0.0.2 通过 record 访问器将五个创建 DTO 的同名同型字段复制到实体公共字段。重命名由 DisplayName record 生成 NameChange record，作用域、凭据、版本和 PATCH 字段存在性由各用例控制。MappingSafetyTest 验证复制值和受保护字段。

== 授权与课程调用

. RouteRegistry 读取 68 项 OAS，WebConfig 与 MVC 路由双向核对，BootstrapService 与中心 sys_api_operation 核对。未登记默认拒绝，固定受保护操作保持 OAS 规定的授权要求。
. TokenService验证RS256、kid/issuer/单aud、sub/iat/exp/jti/tokenVersion；实时读取用户/系统状态和MySQL撤销，先于超级管理员处理。JWT不携带角色或权限claim。
. AuthorizationService先取当前系统启用直接角色，再遍历senior→junior；停用节点切断路径，权限去重、来源可多条；网关按有效角色码检查 requiredRole，课程接口返回协议定义的课程角色码。
. 中心管理同时要求中心API权限、当前组织管理子树及授权上界；系统共享定义写还要求根部门。部门只控制组织管理与直接准入，不是旧业务数据范围；SUPER_ADMIN也不能绕过目标用户部门准入。
. ResourceService仅按UI权限投影MENU/BUTTON；父菜单不授予子按钮。UI↔API映射仅追踪覆盖，不隐式赋权。
. 真实课程端/网关独立于本模块：可信method/path确定operationId；全局准入之后还保留课程Service对象规则。copyCourse的teacher资格不能代替非组长CC；私有authorities端点提供真实API能力，公开Nginx拒绝私有根路径。

不再保留公司、业务scope/selfOnly、旧资源×动作模型、导入管理接口或热力图/统计大屏；dashboard仅基础计数。旧类ImportService、AuthzQueryService、CatalogService不是现行调用链。

== 事务、版本与缓存

管理写过程begin先锁sys_grant_version(id=1)、校验入口/根部门并冻结操作者目标系统授权上界；finish先flush、保护最后有效管理员，再version++与SUCCESS审计同提交。
继承加边在全局锁下检测跨系统、重复和可达反向路径；变更后校验完整闭包提升。移部门还锁用户，检查原/新范围，仅回收不准入的本人指派，不改共享角色。
根实体version处理可选HTTP乐观冲突；它与JWT tokenVersion、全局授权版本是不同机制。

AuthorizationService实现ConcurrentHashMap短期L1和Redis L2；当前源码L1约15秒、L2约5分钟，key为structured:authz:system:user:version。
每次先查MySQL版本，命中/计算后复查版本，变化时重试；事务内直接计算且不读写缓存。TTL仅回收旧键，不能作为撤权延迟窗口。
Redis失败可回源MySQL；版本持续变化或权威数据库不可用不能拿不确定旧快照放行。持久注销不依赖Redis键存在。
上述为实现机制，跨JVM撤权、延迟回填和故障恢复仍须真实验收。

== 审计和三层技术日志

AuditService.success加入调用方敏感事务；denied使用独立事务。外部POST校验可信服务密钥和audit:write后，以独立事务提交，requestId唯一冲突回滚后新事务读取，哈希比较绑定来源系统/主体/规范化载荷；同键异体400。
外部GET校验密钥/audit:read并按当前aud、origin=COURSE及四事件过滤后数据库分页；before/after响应反序列化为JSON对象，操作者只取可信身份快照。

TraceFilter生成traceId，不信任用户追踪头。LayerLoggingAspect覆盖controller/service/mapper，记录traceId/layer/class/method/duration/result/exceptionType，不记录参数、响应、异常消息、token或密钥；AOP不是审计落库入口。
跨课程DB与中心审计DB的同步HTTP不保证分布式原子提交，不能用日志或Mock掩盖未确认错误。

== 运行与验证边界

默认结构化端口8081；无全局context-path；只暴露/api/v1/actuator/health、info。共享密钥与首次root引导凭据必须配置，不提供公开默认root密码。
专用本机测试MySQL/Redis为13306/16379；数据库与缓存前缀必须隔离，禁止生产清库。
现行测试有ArchitectureTest、Rbac1ProtocolRedTest、MappingSafetyTest及Rbac1IntegrationTest；共享HTTP、桌面/手机E2E设施另见link:test-plan.adoc[测试计划]。
实际命令、退出码与失败历史见link:final-acceptance.adoc[最终验收]；结构化行92.52%/分支71.67%、service91.86%。不能从源码存在、健康UP或历史M2报告推导外部部署或未执行的容量/灾备成功。
