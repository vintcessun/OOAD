== 预填调用链：阅读后核对，不代替结论

structured读取：snapshot(user, system) → active → 事务内直接calculate；非事务取MySQL版本→namespace版本键L1/Redis→必要计算→版本复查→缓存。

DDD读取：effective/api → 若外层只读事务则AuthorizationReadTransaction.fresh → stableEffective/stableApi版本括号/必要freshenRead → Policy/graph/缓存；写事务保留未提交事实。

管理模拟：check/explain先认证有权管理员并检查目标范围/状态；停用目标返回正常拒绝，不把管理员身份变成无效。

API决定要把operation.enabled/策略、目标身份和有效权限一起核对；并非只让权限集合缓存新鲜就足够。

== 主审检查项

* [ ] 直接角色/有效角色/权限集合去重，多条来源路径保持可解释，停用中间节点只切对应路径。
* [ ] UI/API kind、system、有效角色码和权限码分别过滤；API的PUBLIC/AUTHENTICATED/PROTECTED与requiredRole/permission不能混同。
* [ ] 验证签名与当前用户/系统/撤销先于旁路；正常allowed:false、401/403/404/503分层解释。
* [ ] 版本化键防旧回填；MySQL版本事实、L1/L2 TTL、两实现缓存结构/TTL不同不意味着合同可不同。
* [ ] 版本复查与只读隔离/持久化上下文分别解决什么；持续不稳定或权威DB不可用不能放行。
* [ ] 事务内不能消费/回填旧缓存；Redis可受限回源，不能笼统称缓存失败总503或总允许。
* [ ] 模拟停用目标时的reason/trace/空effective与缺失目标404，不能用管理员401替代。
* [ ] 共享黑盒每侧独立正确后再比较等价；只排除真实随机值，保留语义关系/分页和路径顺序。
