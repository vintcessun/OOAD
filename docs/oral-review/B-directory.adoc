== 预填调用链：阅读后核对，不代替结论

structured：ManagementController → ManagementService.begin(授权锁/入口/上界) → scope/准入/角色校验 → UserRole或用户部门变更 → finish(版本/成功审计)。

DDD 指派经过 DirectoryController.assign、DirectoryApplicationService.assign、授权锁和管理范围校验，再检查部门接纳及目标系统状态。requireRoleWithin 计算上界，User.assign 校验账号和准入，最后由仓储写入指派并推进授权版本和成功审计。

DDD 调动流程先锁定用户并校验原、新部门的管理范围及版本。跨部门时，User.transfer 清空本人的角色指派，由 save 删除对应记录，并在同一事务中更新授权版本和审计。

两版用户恢复均校验启用系统中保留角色的有效权限及身份标记。两版部门启停按 `rbac:department:status` 和子树校验，仅非根叶部门可停用。删除按 `rbac:department:delete` 校验，成功删除同时清理准入关系。创建、改名和准入替换仍用 `rbac:department:edit`。

== 主审检查项

* [ ] 画清UserRole与DepartmentAllowedRole的两个多对多联结实体，资格不自动授权。
* [ ] 直接指派仅接收roleId，用户当前部门来自数据库；超级管理员也必须满足目标部门准入。
* [ ] 撤销检查当前管理权限、部门范围和assignment属于路径用户，不能凭曾授出就越界。
* [ ] 核对跨部门调动清空本人的角色指派，并检查其他用户的指派和共享角色权限。替换准入时核对不再符合准入的指派。
* [ ] 用户状态/资料/部门独立API；PATCH存在性和显式null、version与不可改字段逐项核对。
* [ ] 分页过滤、稳定顺序、万级用户场景和数据库offset边界；删除部门遇员工/子部门冲突。
* [ ] 用户停用保留指派，恢复检查授权上界。分别核对最后管理员、tokenVersion、拒绝后的用户状态与指派。
* [ ] 普通管理员可原样保留停用系统的准入，变动该集合会被拒绝。仅有部门编辑权限也可成功替换准入。
* [ ] 部门停用保留成员和指派，阻止新建子部门、新建用户、迁入和新指派。使用启停与删除的独立权限验证子树和根部门保护。

== 数据与职责

sys_department、sys_user组织/档案列、sys_user_role、sys_department_allowed_role；与A共享User凭据、与C共享Role关联。汇总其余成员的15表关系而非自行包办。

GRASP：User掌握自己的状态/部门/直接角色，Eligibility掌握允许集合，OrganizationPolicy掌握范围；应用协调跨对象事实和事务。ER使用当前15表，旧公司/scope模型不进入现行解释。

== 必须准备的场景

* 正常场景包含在准入部门中获得角色、跨部门清空该用户全部直接指派，以及在同一部门提交时保留指派。跨部门后可按新部门准入重新指派。
* 等价/边界：不准入、兄弟部门管理员、空角色集合、无用户/无部门、可空PATCH及分页0/1/最大值。
* 异常/并发：assignment属于别人、部门有子节点/用户、调动版本冲突；两次调动后的唯一部门与实际指派一致。
