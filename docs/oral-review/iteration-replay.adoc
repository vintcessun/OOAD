== 由F决定的方法与必须保留的产物

轮数、复演起点的具体组织、独立分支/副本、脚本和实现步骤由F决定。本工作包不执行复演，不替F制造提交。
复演应解释“如果从基线逐步完成，需求/设计/代码怎样演进”，并与当前真实分阶段提交区别；完整实现前的模拟阶段不能借当前最终图冒充当时的计划图。

必须可看到五类变化：

. 需求和关键用例如何确定，计划包图/类图/时序图说明哪些设计意图。
. structured中的过程、图算法与持久化如何逐步形成。
. DDD中的规则如何迁移到对象/Policy，应用层与端口如何协作；外部合同不因对比而改变。
. 身份、资源、缓存、审计和集成的约束如何推动图/测试修订。
. 最终模拟结果与当前基线的对应、缺口和设计代价。

== 每轮记录模板

[cols="1,4",options="header"]
|===
|字段 |必须填写
|性质/轮次 |明确SIMULATION或RETROSPECTIVE；不得写成当年的真实开发记录
|起点/目标 |实际引用SHA、需求编号、预期行为及本轮暂不实现部分
|设计理由 |对象/过程职责为什么这样分配，与上一轮相比变化是什么
|图 |包图、类图、时序图的可维护源和SVG/PNG；区分计划稿与当前代码图
|实现与合同 |实际差异、structured/DDD对照，API/DDL有无变化
|测试 |真实命令与结果；未运行/环境失败/行为RED/GREEN分别标记
|检查 |图中符号与对应轮源码一致；实际打开PNG；解释异常/事务分支
|提交/下一步 |该轮实际commit、未完成项、与最终基线的差异
|===

保留既有真实历史，不改写过去的作者/时间，不把后补分析变成当时设计先行证明。已有link:../iteration-log.adoc[真实迭代日志]和link:../team-history-integration.adoc[团队合并账本]先作只读核对。

== 只读Git汇总工具

link:../../tools/review-history.py[review-history.py]用Python标准库和Git，不需要安装第三方依赖。默认起点为工作包基线，区间为“起点不含、终点包含”。

[source,shell]
----
# 仓库根目录；只向stdout输出，不修改工作树或Git状态。
python tools/review-history.py check
python tools/review-history.py context
python tools/review-history.py history
python tools/review-history.py history --since-ref 84685b7 --until-ref HEAD --format json
python tools/review-history.py history --member F
----

输出包含真实SHA、日期、Git作者、提交标题、第一父差异路径及建议关注人。合并提交按第一父差异理解，不虚称它是某人的新算法；成员过滤是职责关注过滤，不是作者身份识别。
context子命令只核对本地原始资料的大小/指纹，报告缺失或变化，不读取内容到报告，不代表已经阅读。
未提交内容不进入历史；另有workingTreeHasChanges标记。无匹配提交返回空清单，不补造记录；未知路径显示未分类。
脚本不执行commit、push、分支创建或历史重写，不自动签字。私有临时/运行/缓存/原始员工目录的路径不输出，提交标题和作者仍需人工检查再分发。
如需要保存stdout，由F选择本地文件或新的真实审查文档并人工审阅；工具不自动覆盖已有报告。

== 索引维护

link:coverage.json[机器清单]与 link:source-map.adoc[可读索引]列明源码责任，link:api-matrix.adoc[API 责任表]列明现行 68 项中心操作。
源码新增、移动、共享方法改名或OAS操作变更后，`check`失败时先按实际链路补责任，不为通过而删除仍存在的源码或放宽检查。
源码清点覆盖Git跟踪及未忽略的新文件，包括业务代码、测试、配置、SQL、工具、补丁、部署配方和diagrams中的图源/工具；一期图表标historical，图版本协调标coordination，不误当当前业务源码。docs/design中的生成业务图由各人按卡片链接核查，不重复算作程序源码。
不列node_modules/target、锁文件或教师完整缓存。锁文件随对应包/构建负责人了解，不作逐行业务审查。
新增记录只描述真实发生的审查/图文修改/验证；产品缺陷另列问题参考，不擅自修复或修改既有验收报告。
