= 真实课程端集成补充合同

新版教师合同的八个鉴权接口和两个审计接口由权限中心提供，完整清单见 link:api.adoc[API 说明]。
JWT 仍使用身份与有效期声明，/auth/me.permissions 仅返回 UI 权限。
课程管理员凭课程 Bearer 和有效 TEC API 权限查询 /auth/departments、/auth/departments/{departmentId}/users 与 /auth/users/{userId}。
公开边缘转发这些路径并过滤服务密钥头。
实际教师Service的AuthorityCodes（尤其非组长CC）不能从“copyCourse允许进入”推导。
为受控后端补充以下私有提供方接口；它们不是课程业务代理，公开前端Nginx拒绝/integration和/identity根前缀。

* GET /integration/authorities：有效用户Bearer + X-Audit-Service-Key；不接受subject/system参数，取已验证aud；返回裸 `{authorities:string[]}`，只包含当前系统有效API权限码及有效角色码 student、teacher、admin 对应的 ROLE_student、ROLE_teacher、ROLE_admin。未知/停用身份、系统、注销令牌拒绝；服务密钥错误403。只有课程后端持有服务密钥，前端不获得完整API清单。
* GET /identity/users/{userId}：公共稳定身份查询的内网兼容入口；userId是稳定subject字符串。须有效Bearer、服务密钥、当前系统有效TEC API权限及admin身份；返回裸 `{userId:subject,name,no}`。不存在或已删除404 IDENTITY_USER_NOT_FOUND，不返回密码、电话、授权或内部数据库实体。

课程登录的精确 POST /login 经边缘和网关匿名转发，由教师服务校验本地名单、调用统一身份并确认或绑定 subject。
课程页面的学生与教师入口使用课程登录，管理员仍用统一身份中心认证。
课程资源服务器对其余课程业务先本地 RS256/issuer/aud 验证，再中心operationId全局准入检查，然后通过authorities端点装载真实AuthorityCodes和ROLE_身份至SecurityContext；继续执行原Course/Group/Class Service对象规则。
这样课程组长无CC仍能经过teacher全局准入后由Service判定，非组长没有真实CC不能凭全局teacher资格越权。
服务密钥与用户身份缺一不可；客户端伪造X-Forwarded/X-Rbac/operationId头不得成为身份源。

固定教师来源e9a6dff454cc6af23297458320f9c58d469850c9，MIT许可与补丁保留，不将真实选课名单带入源码/镜像。
业务事务提交后，课程集成过滤器用同一 requestId 同步写入脱敏审计。传输故障可重试一次，未确认时返回 HTTP 503 AUDIT_UNCONFIRMED。
